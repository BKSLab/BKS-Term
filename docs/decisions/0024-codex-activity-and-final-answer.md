# 0024 — Ход работы Codex и финальный ответ

Статус: принято, 2026-11-06, preview.34. Дополняет 0015, 0022 и 0023.

Общий bullet не отличает инструмент от сообщения модели: Codex печатает
`Ran`, stdout и комментарии рядом с финальным текстом. Архив начинался с
команд, а длительное выполнение оставалось без сообщений о ходе работы.

Для Codex 0.164.0 добавлено подтверждение activity cells по исходным glyphs,
стилям и структуре. У завершённого exec жирные marker/title; marker обычного
сообщения dim. У stdout отдельный dim gutter. Слово `Ran` само по себе не
меняет роль. Подтверждённый stdout не открывает fences и не создаёт модельные
фазы. Промежуточные сообщения при видимом busy не публикуются как финальный
ответ; их source headers запоминаются, чтобы следующий snapshot не вернул
их во вступление. В ответ попадает модельная часть после последней activity.
Служебные команды пользователя остаются отдельными блоками по ADR 0023.

Длинный видимый заголовок работы может обрезать `esc to interrupt`. Busy
подтверждается положением над исходным полем, dim elapsed/hint, bold Esc и
реальным правым краем для ellipsis. Один elapsed или пауза не являются busy.

TurnSpeech принимает ID текущего подтверждённого работающего запроса. При
пустой очереди и 15 секундах без выданной речи синтезируется одно «Работа
продолжается». Пропущенные интервалы не сохраняются. Фон, набор, настройка
«Вручную» и terminal outcomes снимают допуск. Незавершённый synchronized redraw
временно задерживает выдачу, сохраняя quiet timer: split spinner не должен
бесконечно начинать отсчёт заново. Heartbeat не меняет архив, фазы или Ready.

Основание: actual ConPTY workflow с фиксированными собственными командами,
stdout и 15 233 мс неизменного VT, а также
[exec renderer](https://raw.githubusercontent.com/openai/codex/rust-v0.164.0/codex-rs/tui/src/exec_cell/render.rs)
и [message renderer](https://raw.githubusercontent.com/openai/codex/rust-v0.164.0/codex-rs/tui/src/history_cell/messages.rs).
Visible summary читается только с исходного экрана; скрытые рассуждения не
извлекаются. Тестовый CLI использует собственный изолированный профиль для
двух заранее фиксированных безопасных команд; пользовательские настройки
sandbox/approvals не изменяются. NVDA проверяет человек.
