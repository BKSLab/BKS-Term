# 0010 — Единая доступная область терминала

**Дата:** 27.10.2026

**Статус:** принято по согласованным пяти пунктам доработки TUI

Ручной тест Kimi2.3.3 показал отсутствие эха набора и неудобное чтение запроса
и ответа. Нижний нативный read-only EDIT дублировал графический экран и требовал
отдельного перехода. Это не удовлетворяло основному сценарию доступного терминала.

## Решение

Уточнение0.4.0-preview.6: Shift+навигация переводит фокус в существующий
readonly VT reader, устанавливая каретку по видимому/однозначному программному
курсору или подтверждённой позиции набора. Исходное нажатие выполняет native
EDIT, а не PTY; дальнейшее выделение и копирование использует стандартный
текстовый провайдер. Esc возвращает прежнее управление без CLI Escape.
При неизвестной позиции не создаётся предполагаемое поле редактирования.

Уточнение0.4.0-preview.5 по ручному тесту: пользователь подтвердил речь набора,
но сообщил о сильных рывках при наборе и генерации и отменил пробное нативное
меню выбора/слеш-команд. Его проекция и оформление удалены; Ctrl+Shift+D снова
открывает только прежний обзор. VT рисует отдельный непрозрачный canvas поверх
видимого нативного EDIT в той же области. WS_CLIPSIBLINGS и явный sibling Z-order
изолируют немедленные native EDIT GDI/scroll операции. EDIT сохраняет фокус,
текст, каретку и UIA, но не рисует VT. Изменение его текста/прокрутки не
инвалидирует canvas; его обновляет состояние терминала. Клавиши, mouse selection
и озвучивание остаются прежними; нижнего дублирующего поля нет.

Уточнение0.4.0-preview.2 после ручной регрессии: обычные оболочки сохраняют
прежний нативный редактор команды, выделение, удаление, Tab и журнал. Единая
область прямого ввода по умолчанию предназначена для явно выбранных CLI-профилей;
для других TUI она включается пользователем. Ctrl+Up/Down остаются доступными
для чтения: блоки в обычной оболочке, логические строки в режиме TUI.

Уточнение0.4.0-preview.3: явно введённый простой запуск известного CLI из
командного редактора автоматически передаёт ввод тому же PTY. Это подсказка
по команде пользователя, без зависимости от оформления или версии CLI.
Возврат подтверждается свежей парой OSC133 A/B с тем же приглашением
родительской оболочки; один маркер B и чужое приглашение возврат не разрешают.
Хранится ограниченный отпечаток приглашения. При отсутствии совместимых
маркеров остаётся ручное переключение. Чтение и открытые диалоги сохраняются
до явного возврата пользователя, черновик не отправляется. Переключение
режима не меняет размер ConPTY.

Уточнение0.4.0-preview.4: подтверждение набора учитывает строки фиксированной
ширины с боковыми границами, пробельным заполнением и единственным программным
курсором. Точное появление введённых символов подтверждается между курсорами
до/после; удаляться может только пробельное заполнение. Маска или скрытая вставка
отменяет ожидание, последующее раскрытие не является эхом.

По явному Ctrl+Shift+D однозначный соседний список выбора/слеш-команд получает
нативное представление меню. Нормализация маркеров стабилизирует пункты;
это представление, без вывода исполняемых действий из текста. В общем меню
управление начинается при открытии и использует прежнюю проверку literal keys
по источнику, поколению ввода и полному кадру. Tab и навигация в полном контексте
остаются нативным чтением. Неоднозначный экран сохраняет прежний обзор-снимок.
Оформление использует owner-draw LISTBOX с HASSTRINGS и стандартным провайдером
Windows; High Contrast сохраняет системные цвета. Выбор обновляется без сброса
всего списка. Графический EDIT не теряет WS_VISIBLE при пакетном обновлении.

В прямом режиме нативный EDIT занимает всю рабочую область, а его subclass
рисует существующую VT-сетку через GDI. Штатные текст, UTF-16-каретка и
TextPattern остаются у этого же HWND. Отдельного поля снизу нет. Новые вкладки
CLI-профилей готовы к прямому вводу; обычные оболочки открывают командный редактор.

READONLY сохраняется: источником текста служит CLI. Снятие флага включило бы
штатное NVDA-эхо даже для клавиш, которые приложение скрывает. Вместо этого
ограниченный InputEcho подтверждает только точную видимую вставку, ожидаемую
после пользовательского WM_CHAR. Перерисовки, маски, скрытые ячейки,
неоднозначность, просрочка и смена геометрии не подтверждают ввод. Речь идёт
через существующие UIA Notification; отдельного синтезатора нет.

Ctrl+Shift+L читает логическую строку курсора/подтверждённого видимого ввода.
Для скрытого курсора допустима одна однозначная инверсная ячейка как подсказка
позиции. Это не распознавание поля или команды. При недостатке сведений
сохраняется полный документ чтения.

Ctrl+Shift+R открывает начало изменений после явного Enter. ReplyAnchor хранит
до4096 отпечатков уже доступных строк без дополнительной копии текста. Он
возвращает существующее начало логической строки; неоднозначность использует
текущую страницу. Эта подсказка не определяет смысл ответа AI. Документ
сохраняет независимые закладки; Esc/Ctrl+Shift+Space возвращает ввод и Tab.

Общий нативный диалог по умолчанию показывает стабильный снимок. Явная кнопка
включает живую передачу ограниченного набора пользовательских клавиш, без
вывода действий из текста строк. Каждая клавиша проходит проверку вкладки,
поколения ввода, полного отображённого кадра и готовности PTY. Новая клавиша
не ставится в очередь до ответа/ограниченного срока; повторы и автоматические
подтверждения отсутствуют. Потеря источника/фокуса останавливает управление.
Mapped-действия известного Codex остаются отдельным проверенным механизмом.

Ручная приёмка NVDA обязательна: автоматические проверки подтверждают данные,
маршрутизацию и UIA, но не фактическую речь и удобство взаимодействия.
