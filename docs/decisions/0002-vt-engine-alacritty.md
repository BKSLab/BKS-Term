# 0002 — VT-движок на alacritty_terminal

**Дата:** 24.10.2026  
**Статус:** spike проверен, интеграция в приложение следующим этапом

## Контекст

Текущий `terminal_output.rs` удаляет escape-последовательности и поддерживает только текстовый журнал с OSC 133. Он не хранит экранную сетку, курсор, alternate screen и ANSI-атрибуты. Для Этапа 5 нужна отдельная терминальная модель без изменения ConPTY и существующей доступности.

## Решение

Создать crate `bks-terminal` на `alacritty_terminal 0.26.0` с `default-features = false`. Поток байтов обрабатывать через `vte::ansi::Processor`, а `Term` использовать как владельца основной/alternate сетки, истории, курсора, resize и атрибутов ячеек.

Границы:

- `bks-pty` остаётся собственной обёрткой ConPTY;
- UI получает снимки ячеек, не изменяет RGB процесса и не раскрашивает текст по словам;
- `ansi_palette` приложения применяется только к default/Named/Indexed цветам; явные `Spec(Rgb)` сохраняются;
- профили/сессии и доступный текст остаются отдельными от рендера;
- `terminal_output.rs` и рабочий EDIT не заменяются до проверок новой модели.

## Проверенные API

Локальные исходники подтверждают `Term::new`, `resize`, `grid().display_iter()`, `ansi::Processor::advance`, атрибуты `Cell.c/fg/bg/flags` и `VoidListener`.

## Проверки перед интеграцией

- разделённый UTF-8 и Unicode;
- SGR reset/bold/16/256/True Color, foreground/background;
- clear, alternate screen и resize;
- независимые сессии и отсутствие изменений поведения существующего приложения.

## Последствия

Добавляется внешняя зависимость `alacritty_terminal`. Следующий шаг — проверить модель тестами, затем отдельной итерацией связать её с сессиями и терминальной поверхностью. Полный VT-доступный буфер NVDA и renderer являются отдельной работой, а не следствием добавления crate.
