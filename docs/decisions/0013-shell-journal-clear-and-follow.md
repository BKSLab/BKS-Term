# ADR0013: показ результатов и очистка журнала оболочки

Статус: принято, 2026-10-30.

## Контекст

Пользователь подтвердил цвет и озвучивание preview.8, но после отправки `ls`
журнал сохранял старую прокрутку, а `clear` не удалял старый вывод.
Журнал хранит линейный текст и раньше игнорировал все erase sequences.
Каретка unfocused RichEdit также не гарантирует прокрутку; нативный SB_BOTTOM
может отличаться от inclusive scrollbar boundary на один пиксель.

## Решение

Успешная явная отправка команды показывает журнал и его конец без переноса
фокуса из командного редактора. Дальше авто-follow действует только при
каретке в конце и viewport у конца; выбор старого текста/прокрутка сохраняют
ручное чтение. Прокрутка восстанавливается после включения redraw.

Полный ED2/ED3 в обычной оболочке создаёт событие Clear с каноническим UTF-16
offset. Session отсекает текст/события/стили до последней принятой очистки,
сбрасывает старые блоки и позиции и сохраняет postclear prompt/вывод.
Начальный ED2 остаётся разметкой ConPTY; direct/autoCLI/CLI-profile и
alternate-screen erase не очищают журнал. Команды по их именам не перехватываются.

Пустая ConPTY-разметка после очистки распознаётся только как ограниченный
цикл erase-row/CRLF, завершённый HOME. Обычные postclear переводы строк
сохраняются. Session публикует reset latch даже при отсутствии нового текста.
UI полностью синхронизирует final model, пропуская старые append chunks того
же poll. Retention trim остаётся отдельным событием.

## Проверка

Нативный hidden RichEdit regression проверяет EOF-follow без фокуса и
сохранение исторического выделения при пассивном выводе. Session/parser
fixtures проверяют split/Unicode/style/events, pure clear, несколько очисток,
старый command block при startup и отсутствие удаления журнала от TUI.
Собственные PowerShell/ConPTY проверяют Clear-Host/cls/clear без запуска Kimi.
GUI harness использует только собственный managed shell, literal submissions
через WM_COMMAND и fixture IPC; человеческая NVDA-приёмка выполняется отдельно.
