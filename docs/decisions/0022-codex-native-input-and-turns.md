# ADR0022: ввод и ответы Codex CLI в Windows

Дата: 2026-11-06. Статус: принято для Codex CLI 0.164.0.

## Причина

Нативный Codex в ConPTY запрашивает Win32 input mode (`CSI ? 9001 h`).
CSI-u с модификатором Enter игнорируется этим Windows renderer. Обычный
UTF-8 ввод теряет некоторые знаки пунктуации и комбинируемые символы ещё
до получения запроса провайдером. При длинной вставке Codex публикует серию
промежуточных кадров, переносит textarea и ограничивает её высотой окна.
Во время ответа Tab ставит запрос в очередь, Enter может прервать текущий.
Исчезновение Working совпадает с первым токеном и не доказывает завершение.

## Решение

`codex.rs` хранит политику адаптера, Win32 encoder и проверку раскладки.
`bks-terminal` отслеживает режим 9001 событиями VT parser, включая split
последовательности, reset и границы synchronized redraw. Преобразование
пользовательского ввода применяется только к выбранному Codex после запроса
этого режима. Ответы терминального протокола проходят прежним отдельным путём.
Формат Win32 записей определён в [спецификации Windows Terminal](https://github.com/microsoft/terminal/blob/main/doc/specs/%234999%20-%20Improved%20keyboard%20handling%20in%20Conpty.md).

Модификаторы Enter передаются парой Win32 key-down/key-up. Литеральные BMP
символы передаются как VK_PACKET; supplementary scalars остаются UTF-8,
поскольку surrogate key records меняют повторяемость emoji в реальном CLI.
Полная bracketed paste кодируется атомарно и ограничена 32768 UTF-16 units;
управляющий ESC внутри неё отклоняется до записи. Логический пользовательский
ввод и его wire representation разделены: Submission и SourceInput видят
исходный текст, PTY writer — закодированные bytes.

У нового управляемого профиля проверенной версии включается
`-c tui.disable_paste_burst=true`. Мигрируется только точный неизменённый
старый шаблон после сверки версии и файла. Явные аргументы, имя, папка и
пользовательские настройки имеют приоритет; глобальный Codex config не меняется.

SourceInput сохраняет ограниченное намерение полного ввода. Для полной
большой вставки Codex срок подтверждения 15 секунд; обычный ввод и удаления
сохраняют прежние 750 мс. Каждый опубликованный символ и caret подтверждаются
новым исходным кадром с нужной геометрией/палитрой. Фоновый WRAPLINE в padded
textarea не считается переносом текста. Префикс и суффикс сверяются с точным
принятым содержимым, включая Unicode и настоящие переводы строк.

Скрытая часть длинного draft остаётся приватным намерением и не попадает
в доступное нижнее поле. Поле содержит только подтверждённое source window
и имеет имя «видимая часть ввода». Для архивирования полного запроса
нужен его полный новый echo после отправки; обрезанный суффикс этого не доказывает.

У ConPTY воспроизведён отдельный дефект: во время набора `é []` native cursor
correction (`BS + é + BS`) теряет видимый пробел, хотя провайдер получает
исходный текст. Source model и нижнее поле отражают реальные VT glyphs.
Submission удерживает только ограниченное приватное намерение принятых
литеральных нажатий; противоречивый source caret не переписывает это намерение.
Оно не используется для ввода или озвучивания поля. Явная навигация, неизвестные
controls, меню и смена поля отменяют pending hints. Полный новый echo после
Enter может подтвердить правильный запрос для архива. При ZWSP/сложном ZWJ,
где source не даёт такого подтверждения, остаётся обычное чтение экрана.

Submission передаёт Submit/Queue/Steer из принятого пользовательского нажатия.
TurnLog выбирает ожидающий запрос по свежему полному echo, а не только FIFO:
Steer может обогнать очередь. Preview очереди и управления не становятся
запросом или ответом. Прерванный ответ сохраняется без Ready. Исходный
`Worked for` завершает только свой ответ; постоянно доступный composer
и исчезновение Working не являются завершением Codex.

## Проверка и ограничения

Fixtures `crates/bks-app/tests/fixtures/tui-codex-production30/` содержат
реальные ConPTY bytes, пустые drains, клавиши и время. CLI работал с отдельными
HOME/CODEX_HOME и фиксированным loopback Responses SSE provider, без пользовательских
ключей, внешней модели и tool calls. Для wire fixture отдельно сохранён
логический transport contract. Replay публикует каждый полный synchronized
кадр, не заменяет его конечным screenshot и не истекает parser deadline
искусственным временем записи. Таймеры SourceInput/Submission/TurnLog
используют общую виртуальную шкалу записи.

Неизвестная форма или неоднозначное подтверждение сохраняют полный исходный
экран для чтения. Версии Codex и пользовательские bindings могут отличаться.
Речь NVDA, физическая клавиатура и авторизованный рабочий сервис требуют
человеческой приёмки. Никакие действия не извлекаются из текста ответа.
