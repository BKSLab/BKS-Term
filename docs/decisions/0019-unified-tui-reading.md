# ADR 0019 — единый ввод и чтение TUI

Дата: 2026-10-31. Статус: принято для 0.4.0-preview.17.

## Причина

Переключение с живого TUI к чтению возвращало логические WRAPLINE-абзацы
и исходную заливку. RichEdit склеивал независимые экранные строки;
UIA выдавал целую страницу вместо строки. OpenCode не маркирует каждый
Markdown-ответ ролью Assistant, поэтому прежний архив его не распознавал.
Формы ввода Codex и Claude также отличались от уже поддержанного Kimi.

## Решение

- `tui_reading_document` сохраняет физические строки live-экрана с CRLF;
  отрицательные строки истории остаются логическими. Shell-документ неизменен.
  В режиме прямого ввода этот источник используется для чтения, поиска,
  проекции и анализа ответов. Исключённые строки ввода/меню не возвращаются
  как пустые разрывы между последовательными проекциями.
- Один VisualDocument с отображением UTF-16 позиций используется до и после
  смены фокуса. Стеклянная тема применяется также к чтению и архиву ответов;
  сохранённые VT-цвета не изменяются. Native RichEdit/UIA остаются источником
  каретки и выделения; уход фокуса сохраняет bookmark, EOF включает follow.
- Общий распознаватель поля учитывает панель с отступами, `›`, NBSP,
  горизонтальные границы и многострочный текст. Проекция требует исходных
  координат/стиля/каретки. Принятые клавиши служат только краткоживущим
  доказательством следующего кадра, а не основанием для выдуманного текста.
- ConPTY может завершить redraw со скрытой кареткой, а её позицию прислать
  следующим фрагментом. На срок pending input сохраняется приватное исходное
  поле, с теми же ограничениями 750 мс, 64 символа и геометрии источника.
  Публичное поле на неподтверждённом кадре остаётся пустым. Восстановление
  требует точного принятого префикса и каретки; совпадения палитры недостаточно.
  Частичное подтверждение сохраняет доказательство до полного подтверждения;
  control, смена источника и timeout удаляют его. Анализ ответов не использует
  приватное поле как доказательство готового кадра.
- Стрелки/отмена меню не являются вставкой текста. Для такого split frame
  отдельно сохраняется последнее подтверждённое поле на 750 мс. Возврат
  допускается только при точном совпадении исходного текста, защиты, размеров,
  отступов, edge, rendered styles и palette. Допустимы вертикальное перемещение
  целого поля и текущая исходная каретка. Новое содержимое это доказательство
  не принимает; оно удаляется при возврате видимого кадра, timeout, resize,
  смене режима или отмене direct-сессии. Public stale поле не публикуется.
  Точное подтверждение прежнего текста имеет приоритет над предположением
  о placeholder при каретке в начале: Home меняет позицию, а не владение
  уже введённым текстом. Смена source на скрытом кадре также немедленно
  удаляет continuity, даже если следующий кадр вернётся к прежнему screen.
- Безметочный ответ требует точного принятого запроса в исходной панели.
  После ухода запроса за экран продолжение должно перекрывать уже сохранённый
  текст. Перенос незавершённого слова может заменить только доказанный суффикс.
  Сохранённая панель без текущей каретки недостаточна для приёма такого кадра.
- Активный запрос наблюдает каждый завершённый synchronized frame внутри
  ограниченного PTY drain. Реальное состояние VT-парсера определяет границы;
  буквальная последовательность в OSC/DCS не является доказательством.
  Время не продвигается искусственно между кадрами. UI и речь публикуются
  отдельно при обычном опросе, а не перерисовываются для каждого кадра.
- Готовность требует свежего признака завершения или доказанного возврата
  ввода после работы; тишина, цитата и старый footer не завершают ответ.
  Для парных форматов используются точный echo принятого запроса, маркер
  исходного ответа и структурные границы. Имена приложений/моделей не являются
  условием классификации и не дают разрешения выполнять текст.
- OSC 10/11/12 отвечают фактическими default foreground/background/cursor
  темы, включая обновление темы и HC. Неизвестные palette/clipboard запросы
  не создают действий. Это поддерживает цветовое согласование renderer.

## Проверка и границы

VT-записи установленного OpenCode с локальными фиксированными ответами
проверяют два ответа и 120 абзацев за пределами viewport. Варианты PTY
4096/65536 байт должны сохранить одинаковые кадры и полный ответ ровно один
раз. Нативная UIA-проверка читает текущую и следующую строку отдельно.
Codex/Claude дополнены эквивалентными кадрами из точных версий renderer;
это не проверка авторизованного разговора. Речь NVDA проверяет человек.
