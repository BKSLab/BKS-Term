# 0004 — Два источника доступного чтения

**Дата:** 26.10.2026

**Статус:** принято для Этапа 6

## Решение

### Уточнение прямого ввода в0.2.0-preview.2

Фокус ввода в графический контрол не предоставляет NVDA текст. Поэтому
в прямом режиме под графической сеткой виден отдельный нативный read-only
EDIT с живым VT-документом. Его каретка соответствует VT-курсору, клавиши
маршрутизируются в ConPTY до стандартной обработки EDIT. При скрытом
VT-курсоре используется конец документа. Этот контрол не использует
закладки полноразмерного источника чтения и не меняет черновик команды.

Явная клавиша навигации разрешает один короткий ответ по устойчивому
изменению видимых строк: debounce90мс, максимум300скаляров, срок800мс.
Смена режима, вкладки, фокуса/фона отменяет ответ. Это текстовый feedback,
без построения команд или решений из TUI. Семантический адаптер Codex
остаётся отдельным механизмом. Графический кадр рисуется в memory DC и
одним BitBlt переносится в paint DC; частые очистки не показывают пустой фон.

### Полный документ чтения

Нативные поле команды и журнал остаются стартовым интерфейсом. Журнал
содержит поток и блоки явно отправленных команд; его UTF-16 позиции
сохраняются независимо от координат VT.

«Экран терминала» — отдельный read-only Win32 EDIT с постоянным HWND,
доступным именем и штатным TextPattern. Пользователь выбирает источник
в меню профилей. Документ берётся из основной VT-сетки и её истории,
а в alternate screen — только из альтернативной сетки. Получение
документа не изменяет графический viewport.

Мягкие переносы соединяются в логические строки; жёсткие разделяются
CRLF. Диапазоны UTF-16 сопоставлены с исходными ячейками, включая wide,
combining и surrogate pairs. Снимок имеет версию; запросы чтения не
вызывают выполнения команд или подтверждений.

У каждого источника и вкладки собственные выделение и прокрутка.
Ctrl+Up/Down всегда возвращают к блокам журнала. Переход к чтению снимает
захват клавиатуры; графический курсор дочерней программы остаётся
независимым от позиции чтения. Выбор доступного источника не меняет
стартовый режим новых сессий.

Поиск использует доступную VT-историю и её сопоставление с ячейками.
Подсветка рендера является отдельным слоем и не меняет ANSI-атрибуты.
Клавиши поиска обрабатываются приложением до маршрутизации PTY.

У каждой сессии собственные запрос, текущий результат и состояние строки
поиска. Поиск — буквальная строка без учёта регистра; расширение lowercase
сопоставляется с исходными UTF-16 диапазонами. Неизменная версия документа
пропускается, при новом тексте повторно ищется изменённый суффикс с
перекрытием длины запроса. Очистка и усечение пересчитывают допустимые
диапазоны, сохраняя существующий результат по позиции и контексту.

Ctrl+F открывает нативное поле, F3/Shift+F3 выполняют циклические переходы,
Enter переносит фокус на выделение в VT-документе. Esc и кнопка закрытия
восстанавливают прежний источник и действующий контрол. Из графического
режима поиск оставляет сетку видимой до явного перехода к чтению. Снимок
подсветки копирует только совпадения видимой области, пользовательское
выделение имеет приоритет; исходные ANSI-атрибуты не меняются.

Короткая обратная связь о принятии команды и статусе поиска передаётся
через отдельный видимый STATIC в существующей строке состояния. Он
предоставляет собственный `IRawElementProviderSimple` через `WM_GETOBJECT`
и поднимает UIA Notification (`Other` / `MostRecent`, activity `bks.feedback`).
Нативные EDIT продолжают использовать штатные текстовые провайдеры.
Жизненный цикл notification-provider связан с HWND, внешние ссылки COM
живут независимо; при уничтожении окна провайдер отключается.

Сообщение «Команда отправлена» означает принятие ввода очередью, а не
завершение процесса. Поиск сообщает «i из N» или «Ничего не найдено»
после короткой паузы ввода и сразу при явной навигации. Фоновые обновления
не создают речевых объявлений, отложенное сообщение связано с вкладкой
и запросом и отменяется при уходе или другом явном действии.

Ввод запроса меняет модель поиска и графическую подсветку без повторной
установки выделения в нативном документе. Обновление text/caret этого
документа откладывается на время работы в запросе; Enter или переход
фокуса в reader обновляет документ и выбирает текущий результат. Это
ограничивает лишние текстовые и selection-события для скринридера.

## Проверка

Отдельно проверяются модель документа, состояния чтения/поиска и
реальный UIA TextPattern нативных элементов. Ручная проверка NVDA
остаётся обязательной для пользовательской приёмки.
