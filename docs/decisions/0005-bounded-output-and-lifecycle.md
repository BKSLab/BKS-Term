# 0005 — Ограниченный вывод и завершение сессий

**Дата:** 26.10.2026

**Статус:** реализация Этапа 7

## Ограниченный вывод

ConPTY читает в очередь до 1 МиБ. При заполнении reader ждёт освобождения
места; байты живой сессии не отбрасываются. За один poll берётся до 64 КиБ
из сессии; общий бюджет — 256 КиБ и мягкие 8 мс между порциями, round-robin.
Декодирование UTF-8 и VT продолжается между порциями.

Текстовый журнал ограничен 512 КиБ UTF-8 и 6000 LF; после превышения
удаляется старый префикс до 384 КиБ/4000 LF. По возможности сохраняются
целые строки; одна огромная строка ограничивается по границе Unicode.
Индексы блоков ограничены 4096 записями. VT имеет собственную ограниченную
историю и остаётся отдельным источником чтения и поиска.

Удаление префикса возвращает точное количество UTF-16 units. На эту
величину ребазируются блоки, выделение и позиция чтения. Удалённая
позиция ограничивается началом оставшегося документа. Черновик не меняется.
Постоянный HWND read-only EDIT сохраняется. Обычный вывод дописывается;
при усечении устанавливается готовый ограниченный снимок, после чего
восстанавливаются выделение и viewport. Следование за выводом действует
только для свёрнутого выделения в конце при прокрутке вниз.

Первоначальный предел 4 МиБ/20000 LF отвергнут измерением: удаление
префикса EDIT занимало около 1,1 с, установка снимка около 1,5 с.
Порог проверки отзывчивости оставлен 1000 мс; уменьшен объём журнала.
Это предел истории, а не потеря байтов на пути ConPTY → VT.

Для диагностики задержек можно явно задать BKS_TERM_PERF_LOG. В файл
пишутся только название фазы, длительность от 100 мс и числовой размер;
текст терминала и ввода не журналируется.

## Завершение сессии

Код выхода проверяется только после сигнала process handle, включая
настоящий код 259. После завершения процесса отдельный поток закрывает
HPCON: ConPTY может удерживать output pipe открытым до этого закрытия.
Reader продолжает читать, соблюдая backpressure. Состояние «Завершено»
и однократное уведомление появляются после EOF и опустошения очереди.
Вкладка, последний вывод и код выхода остаются доступны.

Ошибка ввода/чтения хранится в модели вместе с причиной и объявляется
однократно. Ошибка не прерывает обработку уже полученного вывода.
Неисправная сессия не переподключается автоматически. Явное действие
«Перезапустить в новой вкладке» создаёт новую сессию из сохранённого
снимка профиля; прежняя вкладка сохраняется.

Закрытие вкладки передаёт её собственные ресурсы фоновому потоку,
который завершает только принадлежащий сессии процесс и освобождает
ConPTY. Одновременно допускается до 16 таких задач; при заполнении
вкладка остаётся, закрытие можно повторить. Завершённые потоки убираются
при poll. Окончательное ожидание выполняется после закрытия GUI.

## SSH-профили и защищённый ввод

Редактор работает со стандартными Win32 EDIT/COMBOBOX/BUTTON, сохраняет
только имя, адрес или алиас, пользователя, порт и путь к ключу. Аргументы
передаются системному ssh.exe отдельными Windows arguments. Конфигурация
OpenSSH и ssh-agent остаются в ведении OpenSSH; проверки host key не
ослабляются. Сохранение атомарно: модель заменяется после успешной записи.
Неизвестные параметры старого SSH-профиля не перезаписываются редактором.
У работающей сессии отдельный снимок профиля.

Защищённый ввод открывается явно и использует ES_PASSWORD. Диалог владеет
своими клавишами до глобальных сочетаний терминала. Значение очищается из
контрола до callback и направляется в исходную сессию через write, с одним
CR. Оно не проходит через командный редактор, draft или CommandBlocks;
временные UTF-16/UTF-8 буферы диалога очищаются. Поле не отключает эхо
дочернего процесса: пользователь открывает его в ожидаемом скрытом запросе.
Текст TUI не распознаётся как разрешение на ввод или подтверждение.

Git Bash ищется среди настоящих установок Git раньше PATH. Для старого
встроенного профиля git-bash, ошибочно указывающего на WSL bash alias,
путь разрешается заново только при запуске/валидации. Сохранённый JSON и
произвольные пользовательские профили этим не переписываются.
