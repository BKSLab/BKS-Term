# ADR0015: ответы TUI и геометрия доступного вывода

Статус: принято, 2026-10-30. Дополняет ADR0014.

Пользователь запросил уведомление о готовности ответа, переходы между ответами,
озвучивание видимых стадий и исправление смещений рамок. Отдельно подтверждена
проверка общего подхода на предоставленном экране Claude и запуска OpenCode.

`TurnLog` работает с каноническими VT-ячейками, стилями и проекцией вывода.
Кандидат возникает после принятого явного Enter, исключая меню, защищённый
ввод и slash-команды. Ограниченная подсказка из принятых байтов закрывает
быстрый ввод до VT echo; она не меняет отображаемое поле и не генерирует ввод.
Подтверждённые видимые границы выделяют запрос, размышление, поиск, инструмент
и ответ. Неизвестный формат остаётся новым выводом без приписывания авторства.
Названия конкретных программ в классификации не участвуют.

Готовность требует тела ответа и свежего сигнала завершения либо реального
перехода unavailable→editable после busy. Постоянно доступное поле и пауза
не доказывают завершение. Старый статус не становится свежим из-за busy:
он должен исчезнуть из live-области. Ошибки, прерывание и ожидание действия
являются отдельными событиями. Уведомления не меняют фокус и выделение.

Журнал хранит только тела ответов с Unicode и оформлением; ID стабильны,
исправления полного snapshot заменяют прежнюю версию, доказанный overlap
позволяет дописать хвост. Кодовые блоки сохраняют текст, похожий на запросы.
После завершения ответ неизменен. Перерисовка или ED2 не стирают архив.
Предел — 128 записей/2 МиБ, память одной вкладки, без дискового сохранения.
Тот же RichEdit показывает live-проекцию или архив; режим входит в ключ кеша
и поиска, позиции чтения независимы. Ctrl+Up/Down выбирают ответы,
Ctrl+Shift+R — последний; неизвестный TUI сохраняет прежний fallback чтения.
Уточнение preview.32: принятый Enter служебной команды или меню выбирает
исходный вывод после этого действия, даже при наличии ответов. Для нового
запроса модельный архив выбирается после появления нового ID ответа;
до этого доступен исходный вывод. Команды не получают роль ответа модели.
С preview.33 результаты команд сохраняются отдельными блоками общего журнала;
единая навигация и доказательство source snapshot описаны в [ADR 0023](0023-tui-command-output-blocks.md).

Один ограниченный канал речи обслуживает известный и неизвестный TUI-вывод.
Он исключает повторное чтение готового ответа после перехода к passive,
повторы спиннера, накопленную речь фоновых вкладок и речь защищённого ввода.
По умолчанию включены короткая готовность и видимые стадии; звук и полный
ответ — отдельные сохраняемые opt-in. Вручную отключает автоматическую речь.
Скрытые рассуждения и команды из текста не извлекаются и не исполняются.

Геометрия ConPTY измеряется по фактическому шрифту RichEdit, его отступам
и заранее зарезервированной полосе прокрутки. Исходный размер области не
меняется при поиске или подсказках. Для live-сетки исправляются замена шрифта
рамок/блоков и межсимвольная ширина; wide/combining Unicode остаётся по VT.
Live-абзацы после объединения VT soft wraps и архив сохраняют обычный
нативный перенос: длинный текст доступен вертикальной прокруткой без
добавления переводов строк в копируемый текст. Форматирование сохраняет текст,
цвета, выделение, прокрутку и readonly; ненадёжный autoswitch всего Unicode
не отключается. Нативные измерения проверяются со шрифтами Theme для 96
и 144 DPI; фактический переход между мониторами проверяется вручную.

Общий composer поддерживает две горизонтальные линии и prompt справа,
без адаптера Claude. PowerShell 7 предпочитается при обнаружении; явные
профили сохраняются. Профиль OpenCode выбирает нативный npm EXE либо CMD.
ExecutionPolicy и учётные данные пользователя не меняются.

Дополнение 2026-10-31: composer также поддерживает левую полосу, фон и нижнюю
границу без замкнутой рамки. Placeholder, footer и список подсказок исключаются
из ввода. Неразрывные пробелы U+00A0/U+202F допускаются после prompt;
пробелами произвольного текста они не подменяются. При скрытом курсоре
ограниченное evidence принятого ввода (64 символа, 750 мс, исходные позиция
и revision) подтверждается только новым точным VT prefix. Короткая однострочная
bracketed paste даёт такое же evidence; pending bytes не отображаются как ввод.
При недостаточном доказательстве сохраняется исходный терминальный вывод.

Меню без указателя, inverse или отдельного фона требует принятой Up/Down,
новой source revision и взаимного переноса стиля между двумя строками
того же списка. DIM либо неизменные строки определяют обычный стиль;
default foreground сам по себе его не определяет. Для двух равноправных
цветовых ориентаций выбор остаётся неизвестным. Изменение запроса, геометрии,
страницы, неоднозначный перенос и истечение 800 мс сбрасывают доказательство.
Намерение передать фокус потребляется первым новым кадром, даже без меню;
поздний popup не получает фокус от устаревшей клавиши.

Вставка нового ответа перед неподвижным footer обнаруживается по содержимому.
Подсказка отмены означает busy; её исчезновение вместе с подтверждённым
возвратом редактируемого composer может завершить ответ. Новый запрос,
включая повтор того же текста, отделяется только после свежего source echo;
неподтверждённый предыдущий ответ сохраняется без ложной готовности.
Память произнесённых фрагментов ведётся по стадиям: перенос и перерисовка
не повторяют уже прочитанные слова и названия стадий.

Приёмка: pure regressions, нативные hidden RichEdit/UIA проверки и отдельные
`-SingleInput`/`-TuiTurns` сценарии собственного EXE на private desktop.
Реальную речь NVDA, сервисную авторизацию и работу моделей проверяет человек.
