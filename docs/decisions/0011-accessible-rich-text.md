# ADR0011: стили доступных документов и координаты RichEdit

Статус: принято, 2026-10-30.

## Контекст

Classic EDIT передавал текст без ANSI-оформления. Подмена контрола меняет
координаты: модель приложения считает CRLF двумя UTF-16 единицами,
RichEdit/TOM — одной. От этих координат зависят выделение, поиск, каретка,
прокрутка, копирование и якоря блоков.

## Решение

Три доступные поверхности (журнал, VT-документ, прямой ввод) используют
системный RICHEDIT50W из msftedit.dll. Командный редактор остаётся EDIT.
ES_READONLY сохраняется постоянно. Изоляция VT-canvas из ADR0010 остаётся.

ReadingDocument и нормализованный журнал хранят UTF-16 диапазоны TextStyle.
Общий resolver палитры используется GDI и доступным текстом: fg/bg, inverse,
DIM, High Contrast и поддержанные атрибуты имеют одно толкование. Скрытые
ячейки не экспортируют исходный текст или его оформление.

accessible_text хранит канонический исходник и индекс CRLF для каждого HWND.
Только внутренние вызовы переводят позиции между моделью и native CP.
Протокол UIA не перехватывается: клиенты пользуются штатными координатами
и TextPattern RichEdit. Копирование пользователя берёт канонический диапазон.
На границах обновлений соседние CR/LF включаются в одну native замену,
чтобы порции `CR` и `LF` не создавали два абзаца.

Форматирование выполняется EM_SETCHARFORMAT: TOM font setters отвергаются
на ES_READONLY. Операция сохраняет выделение, scroll и event mask и замораживает
перерисовку через TOM. Кеш resolved-диапазонов ограничивает форматирование
изменёнными участками; append не копирует весь исходник. Очистка/retention
перестраивает затронутый документ, уничтожение HWND освобождает кеш и COM.

CSI2026 завершает кадр атомарно либо по таймауту парсера, обслуживаемому
обычным poll даже без новых байтов. Снимки обратной связи строятся только
при ожидающем действии; повторная публикация неизменного документа пропускается.

## Приёмка и ограничения

Нативные тесты используют скрытые собственные HWND, проверяют Unicode,
CRLF/patch/append, выделение, readonly, TOM и реальные UIA foreground/background.
Человек проверяет речь NVDA, формат, меню CLI и воспринимаемое мерцание.
Обратная связь основана на подтверждённых изменениях, а не смысле текста TUI;
неизвестные и неоднозначные состояния не создают автоматических действий.
