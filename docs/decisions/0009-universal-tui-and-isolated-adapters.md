# ADR 0009 — общий доступ к TUI и изоляция адаптеров

Дата: 27.10.2026. Статус: принято в согласованном плане завершения основной разработки.

## Основание

Основной сценарий BKS Term — работа с разными TUI через ConPTY. Поддержка
Codex, Kimi, Claude и Gemini дополняет обычный терминал. Обновление конкретного
CLI может временно отключить расширенную семантику, сохраняя сессию, ввод и чтение.

## Решение

Общая доступность использует VT-модель: доступный документ, каретку, независимый
журнал чтения и ограниченный feedback после явной навигации. Перенос маркера,
подсветки/инверсии и видимого курсора анализируются без распознавания имени CLI.
Одно изменение цвета не доказывает выбор; неоднозначность остаётся обычным текстом.
Фоновая анимация сама по себе не становится запросом решения.

Ctrl+Shift+D предоставляет обзор любого текущего экрана: полный видимый контекст
и нативный список строк. Обозначение возможного выделения служит подсказкой чтения.
Стрелки и Enter в таком списке не передаются в PTY. Явная кнопка возврата к
управлению TUI включает существующий native direct input; дальнейшие реальные
клавиши кодируются стандартным terminal_input с учётом VT-режимов.

Поддержанные mapped actions имеют отдельное представление: распознавание выполняет
скрытый worker-процесс самого BKS Term. Его приватная ветка запуска обрабатывается
до COM, обычных launch options и создания окон. Процесс принадлежит отдельному
Job Object, не содержащему PTY; создание suspended и назначение Job предшествуют
ResumeThread. Общий OwnedChild сохраняет правила жизненного цикла App Server.

UI обменивается с supervisor только ограниченными очередями и не ждёт pipe IO,
распознавание или завершение worker. Протокол JSONL имеет версию, идентификатор
запроса, session/screen/input revision и ограничения размеров. Worker сообщает
известную форму экрана, выбранный индекс и текст контекста; исполняемые байты
определяет только встроенный mapper для явно поддержанной формы/версии.

Перед явным действием UI сверяет исходную сессию, активность, живой процесс,
сохранённый полный VT-снимок и поколения вывода/ввода. Окончательная постановка
использует существующий атомарный session.write_tui/write_when_idle. Текст экрана
никогда не интерпретируется как команда. Неизвестная версия или форма не создаёт
mapped action. Список чтения и обычные клавиши остаются доступны.

Timeout, выход worker, повреждённый/слишком большой ответ или нарушение binding
отключают только улучшение. Нет автоматических циклов перезапуска; восстановление
возможно при следующем явном запросе пользователя. Ранее открытый контекст не
заменяется под читающей кареткой. Файловое evidence поддержанного Codex закрепляется
за запуском сессии; UI timer не читает metadata и не выполняет version probes.

Отдельный процесс обеспечивает изоляцию отказа и не является песочницей для
произвольных сторонних плагинов. Эта версия запускает только собственный worker.
Структурированные API остаются отдельными дополнительными клиентами; переход к
обычной вкладке не обещает переноса их внутреннего состояния.

## Проверки

Покрываются marker/style/cursor feedback, Unicode, ограничения размеров и тишина
при неоднозначных изменениях; read-only overview без PTY bytes; устаревшие снимки;
неизвестные версии/формы; повреждённый/частичный/чрезмерный JSON; отказ/зависание
worker и сохранение независимой PTY-сессии. Человеческая NVDA-приёмка и реальная
работа моделей не выводятся из результатов этих тестов.
