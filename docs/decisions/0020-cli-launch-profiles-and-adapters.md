# ADR 0020 — профили запуска и отдельные адаптеры CLI

Дата: 2026-11-02. Статус: принято по поручению пользователя для preview.25.

## Решение

Общее ядро сохраняет ConPTY, VT, Unicode, передачу клавиатуры, source-ack,
выделение, журнал, тему и нативные элементы доступности. Выбранный адаптер
Codex, Claude, OpenCode, Kimi или Gemini задаёт правила распознавания интерфейса
и семантики. Универсальный адаптер обслуживает остальные TUI. Название
программы само по себе не является доказательством текущего состояния экрана.
Каждый адаптер проверяет исходные координаты/стили и подтверждение ввода;
при неизвестной форме соответствующая возможность возвращается к общему
представлению с сохранением полного текста. Произвольный вывод никогда не
становится командой или подтверждением действия.

Профиль запуска хранит программу, буквальные аргументы, рабочую папку,
переменные среды, адаптер, способ запуска, выбранную оболочку и действие после
выхода. Несколько профилей могут использовать один адаптер. Встроенные профили
служат шаблонами: пользователь создаёт полную настраиваемую копию. Настройки
не запускают процессы; запуск требует отдельного действия открытия профиля.

Аргументы редактируются по одному в стандартном списке, включая пустые
аргументы и пробелы внутри значения. Переменные среды применяются только к
дочернему процессу с Windows case-insensitive правилами; родительский процесс
и другие вкладки не меняются. Значения не записываются в диагностические логи.

## Оболочка и завершение

Прямой запуск использует программу и argv без промежуточного shell.
Запуск через оболочку явно выбирает поддержанный локальный профиль PowerShell,
cmd или Git Bash. Пользовательские аргументы передаются как данные, а не как
фрагменты shell-кода. Неподдержанные сочетания оболочки/аргументов отклоняются
до запуска; они не преобразуются с потерей содержания. WSL и SSH сохраняют
прежний способ запуска и не считаются взаимозаменяемыми Windows-оболочками.

Общая оболочка по умолчанию используется при обычном открытии терминала
без явно выбранного профиля, а также для наследующего CLI-профиля. Отдельный
профиль может переопределить оболочку. Явные --profile и выбор профиля в меню
сохраняют приоритет.

После завершения можно сохранить завершённую вкладку либо открыть выбранную
свежую оболочку в той же вкладке. Последнее выполняется один раз после полного
чтения старого вывода. Это новый процесс: локальное состояние старого процесса
не переносится, команда запуска CLI и недоставленные клавиши не повторяются.
Журнал и архив ответов сохраняются. Исходный профиль остаётся источником
настроек перезапуска, пока его процесс работает.

С preview.26 встроенные CLI-шаблоны и новые пользовательские варианты выбирают
свежую оболочку по умолчанию: завершение программы оставляет работающий терминал.
Явный KeepTab и прежние сохранённые пользовательские профили не мигрируются.

Прежнее ограниченное восстановление аварийной PowerShell после CLI из
ADR0018 сохраняется для обычного запуска команды внутри оболочки. Явное
действие нового профиля после выхода не является повтором CLI или расширением
этого crash-recovery правила.

## Совместимость и проверка

Старые profiles.json читаются с прежним поведением при отсутствии новых полей.
Auto неизвестного старого профиля сохраняет обычный терминал; новый произвольный
CLI выбирает Universal явно. Дублирование фиксирует effective adapter до смены
ID. Discovery добавляет отсутствующие шаблоны и не перезаписывает сохранённые
варианты. Сохранение использует lock, актуальную версию файла и трёхстороннее
слияние: чужие SSH/Local изменения сохраняются, конфликт одного профиля требует
повторного открытия вместо потери данных.

Приёмка: миграция/merge,
literal argv/окружение настоящих дочерних процессов, выход с полным drain,
реальные VT fixtures каждого доступного CLI, native EDIT/COMBOBOX/LISTBOX,
полный cargo pipeline и один независимый проход ревью. Речь и удобство NVDA
подтверждает человек. Документация инструментов и ограничения версий —
в `docs/cli-adapters.md`.
