# 0006 — Управление речью и действия в TUI

**Дата:** 26.10.2026

**Статус:** реализация этапов 8–9

## Озвучивание

Существующий UIA notification provider используется и для автоматических
сообщений. Отдельный TTS не создаётся. По умолчанию выбран режим Important:
однократные события активной сессии. All дополнительно озвучивает новые
устойчивые строки live-screen, Manual оставляет чтение по запросу.
Подтверждения явных действий пользователя не зависят от режима вывода.

Чистая OutputSpeech ограничивает очередь, длину и частоту сообщений,
отбрасывает устаревшее и повторную перерисовку. Фоновый вывод синхронизирует
baseline без воспроизведения при активации. Явный UI feedback имеет приоритет.
Настройка атомарно сохраняется отдельно от профилей в settings.json.

Терминальное ядро предоставляет live_snapshot независимо от display_offset.
История и пользовательская прокрутка не могут стать источником действия TUI.
Обычные текстовые документы и позиции чтения остаются независимыми от речи.

## Первый поддержанный TUI

Версия закреплена: Codex CLI 0.164.0, startup Folder access. Другие экраны,
диалоги, версии, обёртки shell и запуск Codex внутри PowerShell остаются в
обычном режиме терминала. При обнаружении native Codex той версии появляется
отдельный профиль. Discovery выполняет только скрытый ограниченный по
времени `--version`, не читает auth/config и не вызывает модель.

Распознавание требует полного live-screen: заголовка, абсолютного пути,
точного disclosure, двух пунктов с одним выбранным и поддержанного footer.
Фрагменты истории, неизвестный текст, обрезанный путь и неполный экран
отвергаются. Fixtures получены из официального tag rust-v0.164.0; реальный
trust screen в автоматическом прогоне не захвачен. Автоматическая проверка
отклонила первый capture запуск с причиной `blocked by policy`.

Уведомление о доступном диалоге не меняет фокус. Пользователь открывает окно
Ctrl+Shift+D; полный исходный текст находится в read-only EDIT с Tab stop,
варианты в native LISTBOX, отправка — явная кнопка/Enter из списка. Enter в
контексте, стрелки, Esc и закрытие ничего не передают. Quit — отдельный
явно выбранный вариант CLI; закрытие окна само по себе его не выбирает.

Binding хранит session, VT revision, поколение пользовательского ввода,
версию и полный снимок. Изменение этих данных блокирует прежний выбор.
Снимок сверяется непосредственно перед отправкой; финальная условная
постановка в writer атомарна относительно enqueue output: короткий lock
OutputBuffer → InputQueue, проверка пустого вывода и отсутствия in-flight
ввода. Под lock не выполняются filesystem IO, WriteFile или ожидания.
Проверяется доступное BKS состояние; протокольных идентификаторов действий
произвольные TUI не предоставляют, поэтому адаптер ограничен этим статическим
startup запросом. Поддержка новых интерактивных экранов требует отдельной
версии адаптера и новых fixtures/guards.
