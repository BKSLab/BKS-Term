# Проверка Этапа 6

## Итерация 1. Документ VT для чтения

Сборка: `target/release/bks-app.exe`. При запуске сохраняются нативные
поле «Команда» и журнал команд. В меню «Профили» (`Ctrl+Shift+P`) доступны
«Читать экран терминала» и «Читать журнал команд». Первый пункт открывает
отдельное поле только для чтения с именем «Экран терминала» в том же окне.
Правила ввода, захвата клавиатуры и Tab не меняются.

Ниже — ручные сценарии. Проверку NVDA выполняет человек; автотесты её
не подтверждают.

1. Через поле команды выполнить:

   ```powershell
   1..3 | ForEach-Object { [Console]::Write("`rVT_PROGRESS_$_"); Start-Sleep -Milliseconds 400 }
   [Console]::WriteLine()
   ```

   Открыть «Читать экран терминала». В строке результата остался
   `VT_PROGRESS_3`: перезаписанные значения 1 и 2 не становятся отдельными
   строками документа. Журнал команд по-прежнему показывает текстовый поток.

2. Создать историю и очистить текущий экран:

   ```powershell
   1..500 | ForEach-Object { "VT_HISTORY_$_" }
   $e = [char]27
   [Console]::Write("${e}[2J${e}[H")
   ```

   В документе VT история, уже ушедшая за верхнюю границу экрана,
   сохраняется. Повторить с `cls`. Затем выполнить
   `[Console]::Write("${e}[3J")`: удалённая история, например ранние строки
   `VT_HISTORY_1`, больше не доступна. Очистка истории не обязана удалять
   строки, остающиеся на текущем экране.

3. Проверить вход в альтернативный экран и возврат:

   ```powershell
   [Console]::WriteLine(('VT_MAIN' + '_BEFORE'))
   [Console]::Write("${e}[?1049h${e}[2J${e}[H" + ('VT_ALT' + '_ONLY'))
   Start-Sleep -Seconds 15
   [Console]::Write("${e}[?1049l")
   ```

   За время паузы открыть или прочитать документ VT: доступны строки
   альтернативного экрана, основной экран и его история не подмешиваются.
   После выхода снова доступен `VT_MAIN_BEFORE`, содержимое альтернативного
   экрана исчезает. Строки эха команды не принимать за результат.

4. Проверить Unicode, переносы и копирование:

   ```powershell
   [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
   [Console]::WriteLine('Русский English 中 e' + [char]0x301 + ' ' + [char]::ConvertFromUtf32(0x1F600))
   [Console]::WriteLine('VT_WRAP_' + ('x' * 200))
   [Console]::WriteLine('VT_NEXT_LINE')
   ```

   В «Экране терминала» русский текст, широкий символ, комбинируемый акцент
   и emoji читаются и копируются без лишних пробелов от широких ячеек.
   Длинная строка после копирования остаётся одной логической строкой,
   `VT_NEXT_LINE` начинается с новой строки. Явные переводы строк документа —
   CRLF; переносы только по ширине VT не добавляют переводов строк.

5. Прокрутить графический VT-экран к старым строкам, открыть документ
   для чтения и вернуться обратно. Извлечение документа не должно менять
   позицию графической прокрутки. Через Ctrl+Up / Ctrl+Down из документа
   проверить возврат к блокам прежнего журнала. Оба источника должны
   оставаться раздельными.

6. С NVDA проверить имя «Экран терминала», построчное и посимвольное чтение,
   выделение и Ctrl+C, переход Tab к другим элементам. Через UIA проверить
   доступный текст и выделенный диапазон нативного EDIT, включая строки
   истории за пределами видимого экрана. Сравнить скопированный текст
   с результатами сценариев выше. Записать наблюдения; успешная сборка
   и получение UIA-текста не означают, что проверка NVDA пройдена.

## Итерация 2. Сохранение места чтения

1. В командном режиме набрать черновик, не отправляя его. Выбрать
   «Читать экран терминала». Ctrl+Shift+Space переводит фокус между
   выбранным документом и полем команды; оба остаются видимыми, черновик
   сохраняется. Проверить переход также из кнопки или вкладки. Затем
   выбрать «Читать журнал команд» и повторить: сочетание не меняет источник.
   В прямом режиме оно переключает графический VT и выбранный документ,
   каждый раз снимая захват клавиатуры.

2. Через поле команды запустить постепенный вывод:

   ```powershell
   1..300 | ForEach-Object { "VT_READ_$_"; Start-Sleep -Milliseconds 100 }
   ```

   В документе VT вернуться к `VT_READ_20`, выделить часть строки и менять
   ширину и высоту окна во время нового вывода. Проверить сохранение текста
   выделения и логического места чтения после переноса строк. Повторить
   с кареткой в старой строке без выделения: новый вывод не переносит её
   в конец документа.

3. Отдельно проверить все условия автопрокрутки. Поставить каретку в конец
   без выделения и прокрутить документ вниз: новый вывод виден автоматически.
   Затем выделить текст у конца — автопрокрутка прекращается. Наконец,
   оставить каретку в конце, но прокрутить окно чтения вверх полосой прокрутки:
   поступление строк не возвращает окно вниз. Автопрокрутка разрешена только
   при одновременном выполнении всех трёх условий.

4. Сохранить выделение и позицию в основном документе. Выполнить сценарий
   альтернативного экрана из итерации 1; в нём выбрать другое место чтения.
   После выхода восстанавливаются выделение и позиция основного документа.
   Новый вывод и resize в альтернативном экране не должны заменять
   сохранённую позицию основного экрана.

5. Выбрать старую строку истории и выполнить:

   ```powershell
   1..12000 | ForEach-Object { "VT_TRIM_$_" }
   ```

   После вытеснения выбранного фрагмента из ограниченной истории место
   чтения переносится к ближайшей сохранившейся строке, а не к последним
   строкам вывода. Проверить также очистку истории через `ESC[3J` из
   итерации 1: удалённый текст не остаётся в выделении.

6. В двух вкладках оставить разные черновики, источники чтения, выделения
   и позиции прокрутки. Переключать вкладки во время фонового вывода:
   состояние каждой восстанавливается независимо. Ctrl+Up / Ctrl+Down
   из документа VT возвращают к блокам журнала команд; черновик сохраняется.

7. С NVDA повторить чтение старой строки при новом выводе, resize и смене
   вкладок. Проверить, что озвучиваемая позиция соответствует каретке
   документа. Зафиксировать результат вручную; эти сценарии не считаются
   пройденными по сборке или автоматическим проверкам.

## Итерация 3. Поиск и переход к результату

1. При запуске строка поиска скрыта. Оставить черновик команды и нажать
   Ctrl+F: появляется компактная строка над выводом, фокус в поле
   «Поиск по экрану терминала», источник — нативный документ VT. Проверить
   то же из журнала. Из графического VT поиск оставляет графику видимой
   для подсветки; Enter переводит к результату в нативном документе.

2. Для повторяемых результатов выполнить через поле команды:

   ```powershell
   [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
   [Console]::WriteLine(('VT_FIND' + '_Alpha'))
   [Console]::WriteLine(('vt_find' + '_alpha'))
   [Console]::WriteLine(('VT_FIND' + '_Жук 😀 e') + [char]0x301)
   [Console]::WriteLine(('VT_LITERAL_' + 'a.b'))
   [Console]::WriteLine(('VT_LITERAL_' + 'axb'))
   1..500 | ForEach-Object { "VT_FIND_HISTORY_$_" }
   ```

   Запрос `vt_find_alpha` находит обе строки независимо от регистра,
   в том числе в истории за пределами видимого экрана. `VT_LITERAL_a.b`
   находит точку буквально и не находит `VT_LITERAL_axb`. Проверить запрос
   с русским текстом, emoji и скопированным комбинируемым акцентом.

3. При вводе фокус остаётся в запросе. F3 и «Далее» переходят вперёд,
   Shift+F3 и «Назад» — назад. Переход с последнего результата на первый
   показывает «1 из N — с начала», с первого на последний —
   «N из N — с конца». Следующий обычный переход убирает суффикс.
   Очистить запрос: «Введите текст». Ввести отсутствующий текст:
   «Ничего не найдено». Эти клавиши не отправляют команды в PTY.
   После короткой паузы во вводе проверить объявление актуального статуса
   без смены фокуса и автоматического чтения вывода. F3 / Shift+F3 и кнопки
   перехода объявляют статус сразу после действия.

4. Нажать Enter из запроса: выбранный диапазон виден и выделен в нативном
   документе VT, фокус перенесён туда. Индекс совпадения остаётся прежним:
   Enter открывает текущее, для следующего используется F3 или «Далее».
   Прочитать и скопировать совпадение.
   Закрыть поиск через Esc и отдельно кнопкой «Закрыть»: возвращаются
   исходный источник и элемент фокуса, черновик команды сохранён.
   Если исходным элементом был документ VT, выбранное совпадение остаётся
   местом чтения. Повторное открытие сохраняет запрос и текущий результат.

5. В графическом VT проверить подсветку всех видимых совпадений и отдельную
   подсветку текущего. Повторить с цветным текстом, широкими символами
   и комбинируемым акцентом: диапазоны не должны разрезать символы.
   После закрытия поиска остаются исходные ANSI-цвета, символы и курсор.

6. Создать вторую вкладку через Ctrl+Shift+T или «+»: оба способа сначала
   открывают одно меню выбора профиля. Сначала отменить меню через Esc:
   число вкладок, запрос и прежний фокус сохраняются. Повторить другим
   способом, выбрать оболочку и нажать Enter: создаётся вкладка. Оставить
   разные запросы и текущие результаты в двух вкладках; в одной
   вкладке закрыть поиск. При переключении восстанавливаются собственные
   запрос, результат и видимость строки. На фоне нового вывода и resize
   проверить актуальность результатов и отсутствие самопроизвольной
   передачи поисковых клавиш в приложение. В альтернативном экране
   поиск ограничен его содержимым; после выхода используется основной VT.

7. Без открытого поиска F3 и Shift+F3 не запускают навигацию по результатам.
   В явном захвате клавиатуры они передаются приложению, как прочие
   функциональные клавиши. Проверить Tab / Shift+Tab между полем поиска,
   кнопками и документом, а также узкое окно и масштабы 100/150/200%:
   поле запроса и кнопки остаются доступны без перекрытий.

8. С NVDA проверить имя поля и чтение запроса. Набрать существующий запрос:
   после короткой паузы ввода звучит актуальное «i из N». При F3 / Shift+F3 и кнопках
   «Далее» / «Назад» слышен соответствующий счётчик, включая суффикс
   перехода через край; фокус остаётся в запросе или на нажатой кнопке.
   Очистить запрос: «Введите текст». Ввести отсутствующий текст:
   «Ничего не найдено». Повторить переход с таким запросом.
   В этих действиях приложение не начинает читать приглашение оболочки,
   текст выполненных команд или весь документ. Для чтения результата
   отдельно нажать Enter: фокус должен оказаться на текущем выделенном
   фрагменте документа. Проверить возвращение по Esc.

9. С NVDA отправить команду через Enter и отдельно кнопкой «Выполнить»:
   после успешной отправки однократно слышно «Команда отправлена», фокус
   остаётся в поле команды. Shift+Enter добавляет строку без объявления
   отправки. Если команда осталась в поле и не отправлена, подтверждения нет.
   Подождать несколько секунд после ввода запроса и переходов поиска,
   затем повторить с длительным фоновым выводом: объявления не повторяются
   из-за служебных обновлений, каретка и фокус не перемещаются сами.

10. Проверить High Contrast. Исправленные объявления и выбор результата по
    Enter требуют повторной ручной проверки с NVDA. Результат фиксирует
    человек; автоматические проверки UIA не подтверждают успешную озвучку.
