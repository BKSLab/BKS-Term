# Проверка Этапа 5

Сборка: `target/release/bks-app.exe`. Справка: **F1** либо меню
**Профили → Справка**. Ручные проверки ниже не считаются пройденными
на основании автоматических тестов.

## Старт, чтение и навигация клавиатурой

1. При запуске видны нативные поле «Команда» и журнал чтения, фокус находится
   в поле команды. Ввести `echo test` и нажать Enter. Проверить появление
   команды и результата в журнале. С NVDA проверить одно короткое
   «Команда отправлена» после успешной отправки; фокус остаётся в поле.
   Повторить кнопкой «Выполнить». Shift+Enter только добавляет строку.
2. Несколько раз нажать Tab и Shift+Tab: фокус перемещается между полем,
   журналом, кнопками и вкладками в обоих направлениях. В журнале проверить
   перемещение каретки, выделение и Ctrl+C. Фоновый вывод не должен менять
   фокус и позицию чтения.
3. Включить «Прямой ввод» через Ctrl+Shift+P. Поле команды скрывается,
   появляется VT-экран. Без захвата Tab и Shift+Tab продолжают перемещать
   фокус по интерфейсу; сам переход на VT не отдаёт Tab процессу.
4. Явно включить захват клавиатуры через Ctrl+Shift+I или меню «Профили».
   На VT-экране Tab теперь передаётся оболочке для автодополнения.
   Повторное Ctrl+Shift+I возвращает Tab навигации по интерфейсу.
   Отдельно проверить, что Ctrl+Shift+Space и F1 снимают захват.
5. Проверить Alt+Tab без захвата и с захватом: Windows переключает
   программы, клавиша не застревает в терминале. После возвращения
   проверить фокус и состояние захвата; при необходимости включить его
   явно перед следующим вводом в VT.

## Терминал

1. Включить «Прямой ввод» и явно захватить клавиатуру через Ctrl+Shift+I.
   Выполнить `echo test`, `pwd`, `git --version`, `git log -5`. Проверить стрелки,
   Backspace, Delete, Home/End и автодополнение Tab. Нажать Esc:
   окно остаётся открытым, клавиша передаётся оболочке.
2. Выполнить `cls`: экран очищается, prompt и курсор остаются рабочими.
3. В PowerShell проверить палитру:

   ```powershell
   [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
   $e = [char]27
   [Console]::WriteLine("${e}[31mКрасный ${e}[42mФон${e}[0m")
   [Console]::WriteLine("${e}[38;5;214m256 ${e}[38;2;85;170;255mTrue Color${e}[0m")
   [Console]::WriteLine("Русский English 中 e$([char]0x301) $([char]::ConvertFromUtf32(0x1F600))")
   ```

   Цвета должны различаться, комбинируемый акцент не сдвигает следующие
   символы, широкий символ занимает две колонки. Вид конкретных emoji
   зависит от доступных шрифтов и GDI. Для `[Console]::WriteLine` здесь
   явно задан UTF-8: Windows PowerShell может заменять символы, которые
   отсутствуют в его текущей кодировке вывода.
4. Проверить alternate screen без дополнительных программ:

   ```powershell
   [Console]::Write("${e}[?1049h${e}[2J${e}[HALTERNATE SCREEN")
   Start-Sleep 2
   [Console]::Write("${e}[?1049l")
   ```

   После двух секунд должен восстановиться предыдущий основной экран.
   В установленном полноэкранном CLI дополнительно проверить навигацию,
   выход и изменение размера окна. Конкретную программу и её версию
   указать в обратной связи.
5. Выполнить `1..10000 | ForEach-Object { "Строка $_" }`. Во время вывода
   менять размер окна и переключать вкладки. Проверить историю колесом
   и Shift+PageUp/Down, возврат Ctrl+Shift+End. Новый ввод возвращает
   экран к текущему курсору. История VT ограничена 10 000 строками.
6. Выполнить `ping -t 127.0.0.1`, остановить Ctrl+C. Проверить, что
   следующая команда работает. Не закрывать чужие сеансы для проверки.

## Режимы, копирование и вкладки

1. Ctrl+Shift+Space открывает нативный журнал. Выделить старый текст,
   дождаться нового вывода: выделение, позиция чтения и фокус сохраняются.
   Повторное сочетание возвращает к VT без автоматического захвата.
   Tab перемещает фокус по интерфейсу; для ввода в процесс снова явно
   включить захват через Ctrl+Shift+I.
2. Выделить текст на VT-экране мышью, скопировать Ctrl+Shift+C.
   Проверить русский, wide/combining и строки с переносом. В журнале
   стандартный Ctrl+C копирует выделение.
3. Вставить безопасный однострочный текст через Ctrl+Shift+V и Shift+Insert.
   Проверить многострочную вставку в приложении с bracketed paste:
   это обычная явная вставка в процесс, переводы строк могут выполнять
   команды в оболочке. При захвате Ctrl+V передаётся самому процессу.
4. В меню Ctrl+Shift+P снять «Прямой ввод»: видны поле команды и нативный
   журнал, захват выключен. Выполнить команду через поле,
   затем многострочную команду с Shift+Enter. После трёх команд из поля
   нажать Ctrl+Up: фокус переходит к последнему блоку. Повторные Ctrl+Up
   переходят к предыдущим, Ctrl+Down — к следующим. Проверить крайние
   блоки, черновик поля команды, Ctrl+Down из поля (первый блок), а также
   прежние Alt+Up/Down и Ctrl+Shift+C. Блоки результатов создаются для
   командного редактора; прямой Enter блок не создаёт.
5. Нажать Ctrl+Shift+T: появляется тот же выбор профиля, что и по кнопке
   «+». До выбора новая вкладка не создаётся. Нажать Esc: меню закрывается,
   прежний фокус и черновик сохраняются. Повторить открытие и отмену
   кнопкой «+», сравнить доступные профили. Повторно открыть меню, выбрать
   профиль и нажать Enter: создаётся независимая вкладка выбранной оболочки.
   Создать три вкладки, запустить длительный вывод в первой. Переключать
   Ctrl+Tab, Ctrl+Shift+Tab и Alt+1…3. Экран, история, режим чтения,
   черновик и результаты каждой вкладки должны оставаться независимыми.
   Закрыть вкладку, проверить обе ветки подтверждения: «Нет» и «Да».
6. Свернуть и восстановить окно, перейти в другую программу и обратно.
   Ввод должен продолжиться в видимом элементе текущего режима.

## Справка и доступность

1. Открыть F1, прочитать и скопировать текст, перейти Tab к «Закрыть».
   Повторный F1 не создаёт второе окно. Esc закрывает только справку
   и возвращает прежний фокус. Вывод в терминале продолжается.
   Если справка открыта из захвата, после её закрытия Tab снова
   перемещает фокус по интерфейсу.
2. С NVDA проверить чтение справки, меню профилей, вкладок и журнала;
   построчное/посимвольное чтение, выделение, копирование и возврат к вводу.
   Проверить отсутствие потери позиции и самопроизвольного переключения
   фокуса при фоновом выводе. «Команда отправлена» не повторяется по таймеру
   и не объявляется для команды, которая осталась в поле без отправки.
3. Проверить реальный системный масштаб 100/150/200% и High Contrast.
   Сетка, курсор, выделение, кнопки и справка не должны перекрываться.

Доступный журнал пока представляет очищенный поток, а не полный снимок
VT/TUI. Полная доступная проекция и поиск остаются Этапом 6.

## Автоматическая проверка окна

```powershell
pwsh -NoProfile -File scripts/check-stage5.ps1
```

Скрипт создаёт отдельный процесс с отдельным `APPDATA` в артефактах и
проверяет прямой Unicode-ввод, режимы,
справку, возврат фокуса, командный редактор и независимость двух вкладок.
Для сочетаний клавиш временно активирует своё окно. Закрывает только
созданный процесс. Результаты и снимок — `target/stage5-check/`.
Он не проверяет речь NVDA и не заменяет перечисленные ручные сценарии.
Прежние 22 автоматические проверки не подтверждали доступность и не
являются её приёмкой. Работу с NVDA проверяет человек.

Отдельная проверка UI Automation и клавиатуры:

```powershell
pwsh -NoProfile -File scripts/check-accessibility.ps1
pwsh -NoProfile -File scripts/check-accessibility.ps1 -Shell Cmd
```

Проверяются реальные UIA-имена, текстовые диапазоны, выделение, read-only,
цикл Tab/Shift+Tab, ввод и возврат фокуса. Скрипт использует системный
клиент UIA из Windows PowerShell, отдельный процесс и APPDATA; буфер
обмена не меняет. Артефакты — `target/accessibility-check/`. Эти проверки
показывают предоставленные Windows свойства, но не проверяют речь NVDA.
