# Границы предварительной версии

- В preview.34 финальный ответ Codex отделяется от подтверждённых инструментальных
  блоков по исходной отрисовке версии 0.164.0. Периодическое сообщение о работе
  требует видимого подтверждения busy; один таймер не доказывает работу или
  готовность. Неизвестные форматы остаются доступны в исходном чтении.
  Реальные workflow-записи выполняли только фиксированные команды над собственным
  тестовым файлом в изолированном профиле; sandbox/approvals рабочего профиля
  этими записями не проверялись. Речь NVDA требует ручной приёмки.
- С preview.33 подтверждённый вывод служебной команды Codex, например `/status`,
  сохраняется отдельным блоком общей истории вместе с ответами модели.
  История ограничена 128 блоками / 2 МиБ в памяти вкладки; результат одной
  команды — 128 КиБ с отметкой при обрезке. Предыдущие запуски не восстанавливаются.
  Для сохранения требуется явная отправка команды, видимый результат с её
  исходным echo и подтверждённый возврат пустого поля. Неоднозначные форматы,
  защищённый ввод и меню остаются в исходном документе. При его очистке CLI
  несохранённые строки могут исчезнуть. Старые окна preview.32 не получают новый архив.
- В preview.30 нативный Codex CLI 0.164.0 проверяется по реальным ConPTY
  записям и фиксированному loopback провайдеру. Прочие версии и пользовательские
  привязки клавиш требуют повторной проверки. Первая полная вставка ограничена
  32768 единицами UTF-16; длинный редактор показывает только исходное окно
  текста. Скрытая часть не публикуется как подтверждённый нижний ввод.
  Полный запрос архивируется только после полного нового echo самого Codex.
  Неизменённый управляемый профиль отключает сворачивание вставок для своего
  запуска; явные пользовательские параметры сохраняются. Обновление профиля
  не изменяет уже запущенный CLI. Речь NVDA и рабочая авторизация остаются
  отдельной человеческой приёмкой.
  В части составных Unicode-последовательностей (знак ударения с последующим
  пробелом, ZWSP, ZWJ emoji) Windows
  ConsoleHost может выдать VT-текст, отличающийся от точного запроса провайдеру.
  При таком несовпадении поле и архив не подставляют предполагаемые символы;
  исходный экран остаётся доступен для чтения. Если после Enter полный новый
  echo подтверждает исходный запрос, архив сохраняет его целиком; иначе доступен
  обычный вывод без выдуманной пары. Exact Unicode transport сам по себе
  не доказывает точность исходного renderer.
- В preview.26 профили выбирают отдельные стратегии CLI поверх общего VT/native
  ядра. Неизвестная форма остаётся доступна полным экраном. Codex/Claude/Kimi
  проверены настоящими renderer с фиксированными loopback-ответами; OpenCode
  имеет также captures меню/ошибок. Авторизованные сервисы и речь NVDA в эту
  проверку не входят. Gemini сейчас не установлен: проверены официальные
  документы и структурный fallback, не live-сессия. Подробности — `cli-adapters.md`.
- В очереди Kimi без самостоятельной idle-границы первый ответ сохраняется
  как incomplete; это не препятствует переходам между его текстом и следующим
  ответом. Подсказка очереди остаётся исходным control text вне архива ответов.
- Запуск через оболочку поддерживает обычные локальные PowerShell, cmd и Git Bash.
  CMD допускает только аргументы, для которых гарантируется буквальная передача;
  пустые значения, пробелы и метасимволы требуют другого способа запуска.
  Для собственного скрипта можно явно указать интерпретатор как программу,
  а путь и параметры — отдельными аргументами. Произвольные startup-команды
  профиля оболочки не используются как неявная подготовка другого CLI.
- После CLI действие «Открыть оболочку» создаёт свежий процесс в настроенной
  папке. Журнал/архив сохраняются, переменные и функции старого процесса не
  переносятся. Сохранение настроек обновляет profiles.json до schema 2;
  предыдущие сборки не должны редактировать этот формат. Старые файлы читаются.

- В preview.17 ввод и чтение OpenCode используют один физический документ
  и одну тему. Регрессии воспроизводят захваченные кадры установленного
  OpenCode 2.0.32 с локальным провайдером фиксированных ответов; модельных
  сетевых запросов и действий по тексту ответа не было. Codex 0.164.0 и
  Claude 2.1.240 первоначально проверялись по эквивалентным кадрам renderer.
  В preview.24 добавлены реальные изолированные editors обоих CLI: Unicode,
  каретка, удаление, очистка и slash-меню без запросов к модели. Подсказка
  Codex с одной padding-строкой и правым footer распознаётся как пустой ввод.
  Авторизованные ответы этих двух сервисов и речь NVDA требуют ручной проверки.
- Архив ответов требует подтверждённого запроса и границ исходного вывода.
  Неоднозначные страницы, промежуточные кадры и неизвестные форматы доступны
  в полном экране терминала, но не объявляются готовыми ответами.
- В0.4.0-preview.17 стекло охватывает всё окно на поддерживаемых Windows 11 22H2+.
  Для сохранения эффекта без фокуса используется изолированный Accent Acrylic
  backend: его accent policy — compatibility API, а не гарантированный контракт
  DWM. При отказе API используется системный Desktop Acrylic, который может стать
  непрозрачным без фокуса. Windows 10, запрет прозрачности, High Contrast и политика
  системы могут дать непрозрачный фон; интерфейс остаётся рабочим.
  Визуальное оформление не заменяет ручную проверку NVDA.
- После выхода установленного OpenCode 2.0.32 воспроизведён сбой PowerShell 7
  `0x80131623`: её консольный handle отключается. Preview.16 восстанавливает
  стандартный локальный профиль одной попыткой в той же вкладке после полного
  чтения завершающего вывода. Журнал и черновик сохраняются; локальные переменные
  теряются, рабочий каталог берётся из профиля. Произвольные startup scripts,
  CLI-only профили, обычный exit и другие коды завершения не перезапускаются.
  Самостоятельная сессия CLI завершается штатно; перезапуск доступен в меню профилей.
  Preview.24 сохраняет исходное пятисекундное окно после возврата CLI также
  при первой поставленной в очередь shell-команде: enqueue ещё не подтверждает
  доставку. Следующие команды окно не продлевают; exact CLR-код и полный drain
  остаются обязательными. Команда из старой очереди не повторяется.
- В0.4.0-preview.12 исправлены общие различия полей OpenCode и Claude:
  неполная рамка/фон панели и NBSP после приглашения. Меню с одним лишь
  цветом/приглушением требует первой принятой стрелки и подтверждённого
  переноса оформления; до этого оно остаётся обычным доступным выводом.
  В меню из двух пунктов без DIM два равноправных цветовых варианта остаются
  исходным выводом: default foreground не доказывает обычное состояние пункта.
  Для неизвестных или компактных форм первая большая/многострочная вставка
  может остаться в исходном экране без проекции нижнего поля. Ввод в PTY
  сохраняется. Встроенный профиль OpenCode в preview.28 включает полный показ
  вставки и проверяет её исходный текст до 32K; явно унаследованные inline-
  настройки CLI и пользовательские профили сохраняют свой режим отображения.
  Реальный изолированный OpenCode проверен без модельных запросов; поле
  Claude проверено по установленному renderer и эквивалентным VT-данным.
  Приватный Claude остановился на диалоге доверия, который не подтверждался;
  авторизованный REPL и реальную речь NVDA проверяет человек.
  Подсказка отмены, которая остаётся на экране, не считается завершением
  ответа. Новый подтверждённый запрос сохраняет предыдущий незавершённый
  ответ отдельно, не объявляя ложной готовности.

- В0.4.0-preview.11 готовность распознанного ответа требует свежего сигнала
  завершения либо подтверждённого возвращения недоступного во время работы
  поля ввода. Молчание и постоянно доступное поле не доказывают завершение.
  Общая эвристика использует только видимый текст и оформление; неизвестный
  формат остаётся «Новым выводом», без выдуманных границ ответа. Текст скрытых
  рассуждений не извлекается. Журнал ответов ограничен 128 записями/2 МиБ,
  находится в памяти вкладки и не восстанавливается после закрытия приложения.
  Перекрывающиеся запросы без подтверждённой границы TUI автоматически
  не разделяются на отдельные ответы.
  Правильность фактической речи и звука NVDA проверяет человек.
  Новое распознавание разделителей проверено на фикстуре предоставленного
  экрана Claude, не на авторизованном сеансе сервиса. Его `Login expired`
  требует входа в самом Claude. OpenCode в явном Windows PowerShell 5 может
  требовать `opencode.cmd` при запрете PS1; политика системы не изменяется.

- В0.4.0-preview.10 общее нижнее поле отражает ввод TUI. Распознанные поле,
  рамка и меню не дублируются в верхнем выводе. Границы должны подтверждаться
  курсором и структурой экрана; при неоднозначности сохраняется полный экран,
  нижнее поле остаётся пустым прямым вводом. Скрытые и боковые области не угадываются.
  Выделение поля — для чтения/копирования; редактирование принадлежит приложению.
  Удаление старых копий поля из scrollback требует сохранённых доказательств
  положения строк. При смене геометрии или пределе 10 000 строк неоднозначная
  история сохраняется целиком; произвольные прошлые рамки не удаляются.
  Фактическую речь NVDA, меню и удобство общего поля проверяет человек.


- В0.4.0-preview.9 явная отправка shell-команды переводит показ на новый
  результат в журнале. Очистка журнала следует полным VT erase sequences
  обычной оболочки; TUI/direct/alternate-screen перерисовки историю не удаляют.
  Частичная очистка строк и перемещение курсора не превращают линейный журнал
  в полную копию VT. Стартовая разметка ConPTY не стирает принятый блок команды.

- В0.4.0-preview.8 живой ввод фокусирует поверхность терминала, чтобы NVDA
  не применяла к стрелкам TUI чтение каретки нативного редактора. Styled
  документ доступен через Ctrl+Shift+Space. Фактическое исчезновение лишних
  `/`, `)` и речи указателей в реальном Kimi проверяется человеком.
  Возврат из CLI, запущенного через прямой ввод, требует точной введённой
  команды и свежего совпадающего prompt родителя. История/сложное редактирование
  не восстанавливаются по тексту экрана. Пользовательские NO_COLOR/FORCE_COLOR
  сохраняются; терминал исправляет собственные TERM/COLORTERM capabilities.

- В0.4.0-preview.7 нативный RichEdit передаёт цвета и оформление документов
  VT/прямого ввода/журнала. Автотесты проверяют реальные UIA-атрибуты цвета,
  Unicode, CRLF и сохранение выделения. Речь NVDA, навигацию по формату,
  выбор модели/слеш-команды, мерцание и системный High Contrast проверяет человек.
  Обратная связь редактирования требует подтверждённого видимого изменения;
  скрытая позиция не угадывается. Фактическая причина прежнего молчания `/model`
  без воспроизведения не считается установленной. Диагностика включается явно
  через `BKS_TERM_TUI_TRACE` — см. ручную приёмку.

- В0.4.0-preview.6 Shift+навигация выделяет доступный текст для чтения и
  копирования от известного курсора TUI. Это не редактирование CLI-запроса;
  Esc возвращает ввод. Если приложение не показывает позицию, произвольный
  курсор не угадывается. Подсказки пунктов очищают подтверждённый указатель;
  неоднозначные маркеры/стили не дают автоматической речи. Фактическая работа
  выбора модели Kimi после этих правок проверяется человеком.

- В0.4.0-preview.5 удалено пробное нативное меню выбора/слеш-команд. Собственный
  TUI и Ctrl+Shift+D обзор сохраняются. Рисование VT отделено от нативного
  текстового поля в той же области, чтобы его прокрутка не сдвигала изображение.
  Пользователь подтвердил озвучивание набора вpreview.4; оно сохранено.
  Отсутствие рывков и речь после изменения слоя отрисовки проверяются вручную.

- В0.4.0-preview.4 исправлено подтверждение набора в строках фиксированной
  ширины с рамкой и программным курсором, как у Kimi. Реальную речь проверяет
  человек. Пробное меню этой версии удалено вpreview.5.

- В0.4.0-preview.3 простые запуски известных CLI из поля команды автоматически
  включают TUI. Аргументы, составные команды и неизвестные инструменты сохраняют
  ручное переключение Ctrl+Shift+I. Автовозврат требует совместимых OSC133-маркеров
  и совпадающего приглашения родительской оболочки; при другом/динамическом prompt
  можно явно вернуться к командному режиму через меню. Пустые стартовые строки
  разметки после первоначальной очистки не попадают в журнал; сам VT-экран сохранён.
  Повтор старого экрана при последующем физическом resize не дедуплицируется вслепую.

- В0.4.0-preview.2 исправлена регрессия обычной оболочки изpreview.1:
  нативное поле команды, выделение/удаление, Tab и Ctrl+Up/Down восстановлены.
  Единая область TUI включается в отдельных CLI-профилях или явно через
  Ctrl+Shift+I. Ctrl+Up/Down в TUI служат чтению; объект системной каретки
  сохраняется для доступности, её лишнее изображение скрывается.

- В0.4.0-preview.1 реализована единая область ввода/чтения, эхо только
  подтверждённой видимой вставки и явное живое управление в нативном TUI-диалоге.
  Фактическую речь NVDA и удобство Kimi после этих изменений проверяет человек.
  Эхо может объединять быстрые символы; неизвестная/неоднозначная вставка,
  скрытый курсор без подтверждённого положения и смена геометрии требуют
  обычного чтения экрана. Поиск нового вывода не определяет смысл «ответа AI».

- В0.2.0-preview.2 исправлен прямой ввод через отдельное нативное поле с
  живым VT-текстом и кареткой. Обратная связь после явной навигации сравнивает
  видимые строки, а не семантику произвольного CLI. В0.3.0-preview.1 учитывается
  однозначный перенос fg/bg/inverse между строками и переход видимого курсора.
  Одиночная смена цвета, смена темы и неоднозначность остаются тихими; при скрытом
  VT-курсоре используется однозначный программный курсор или подтверждённая
  позиция видимого ввода; без них — конец документа. Две произвольные custom-style строки
  без признака обычного оформления могут потребовать ручного чтения.
  Проверка реальной речи NVDA и мерцания Kimi после исправления остаётся ручной.
- Речь NVDA, реальный вход/модель Codex, удалённый SSH, рабочие WSL/Docker
  сценарии и запуск на втором чистом ПК/VM требуют ручной проверки.
  Наличие WSL и Docker на машине пользователя подтверждено; прежний probe
  показывал недоступный daemon и только docker-desktop в WSL, а не отсутствие ПО.
- При fallback Ctrl+Shift+D открывает обзор любого TUI; список строк здесь не является меню CLI:
  по умолчанию он перемещает только чтение. Явный режим «Управлять клавишами TUI»
  передаёт только нажатые пользователем клавиши. Возможное выделение — подсказка по оформлению.
  Размер обзора ограничен256строками/512колонками/65536символами; об усечении
  сообщается, полный доступный документ остаётся в обычном reader.
- TUI-адаптер закреплён за Codex CLI0.164.0 startup Folder access проверенного
  профиля. Fixtures source-derived; живой trust capture не подтверждён.
  Первоначальный автоматический capture отклонён с `blocked by policy`.
  Другие экраны/версии работают через обычный доступный терминал и обзор.
  Изоляция собственного worker не является песочницей сторонних плагинов.
  Таймаут/ошибка worker отключает mapped actions; повторный анализ — явным
  Ctrl+Shift+D. Работающая PTY-сессия не перезапускается.
- Обнаружение Codex/Kimi/Claude/Gemini проверяет только локальные version/help,
  не реальный разговор/модель/разрешение. Подтверждены Codex0.164.0, Kimi2.3.3,
  Claude2.1.240 и изолированный Gemini0.65.0; последний установлен только под target
  с отключёнными install scripts/optional dependencies. Его native keytar/node-pty
  и полноценный TUI этой установкой не проверены. Общая пользовательская установка
  Gemini не выполнялась. Обычный TUI-профиль сохраняется при неизвестной версии;
  AX-профиль предлагается только при подтверждённых version/help флагах.
- App Server — отдельный read-only text frontend0.164.0 с ограниченным набором
  событий и разовыми command approvals. Нет импорта прошлых threads, файлов,
  network/persistent permissions или автоматического повтора в PTY.
- В Git for Windows2.55.0.windows.4 supplementary Unicode во введённой
  интерактивной команде может превратиться в U+FFFD. Изолированный probe
  подтвердил: входные UTF-8 bytes `41 f0 9f 98 80 42` сохраняются в ConPTY
  как D83D+DE00 KEY_EVENT_RECORD; clean Bash возвращает `41 ed b8 80 42`.
  Потеря локализована после нативного ввода на пути Git/MSYS. Кириллица/CJK,
  combining и генерируемый самим Bash emoji проходят. Команды намеренно
  не переписываются и не сохраняются во временные скрипты ради обхода.
- All озвучивает устойчивые строки, а не каждый пиксель/изменение строки TUI.
  Неоднозначные перерисовки доступны для чтения вручную. История ограничена.
- Новое окно — отдельный процесс. Недавние профили содержат начальную папку;
  команды `cd` внутри shell не превращаются в автоматически сохраняемое состояние.
- Блокировка конфигурации не ждёт другое окно: занятой файл/конфликт нужно
  открыть и сохранить заново. Пути конфигурации через reparse points отвергаются.
- Setup и EXE не имеют подписи издателя. Setup использует системный .NET
  Framework bootstrap; portable EXE не требует Rust/Build Tools/.NET/VC Runtime.
  Проверку на чистой Windows этим утверждением не подменяем.
- CI подготовлен в репозитории; без push он не выполнялся на GitHub.
  Реестр Проводника не меняется при обычном запуске/установке. Его реальная
  регистрация и поведение Explorer ожидают явного пользовательского запуска.
- Автотест реального file-symlink не смог создать ссылку из-за Windows1314;
  повышения прав не запрашивалось. Пять настоящих directory-junction с
  внешними sentinel-файлами проверили ту же защиту путей успешно.
