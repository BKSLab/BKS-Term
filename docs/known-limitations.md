# Границы предварительной версии

- В0.4.0-preview.6 Shift+навигация выделяет доступный текст для чтения и
  копирования от известного курсора TUI. Это не редактирование CLI-запроса;
  Esc возвращает ввод. Если приложение не показывает позицию, произвольный
  курсор не угадывается. Подсказки пунктов очищают подтверждённый указатель;
  неоднозначные маркеры/стили не дают автоматической речи. Фактическая работа
  выбора модели Kimi после этих правок проверяется человеком.

- В0.4.0-preview.5 удалено пробное нативное меню выбора/слеш-команд. Собственный
  TUI и Ctrl+Shift+D обзор сохраняются. Рисование VT отделено от нативного
  текстового поля в той же области, чтобы его прокрутка не сдвигала изображение.
  Пользователь подтвердил озвучивание набора вpreview.4; оно сохранено.
  Отсутствие рывков и речь после изменения слоя отрисовки проверяются вручную.

- В0.4.0-preview.4 исправлено подтверждение набора в строках фиксированной
  ширины с рамкой и программным курсором, как у Kimi. Реальную речь проверяет
  человек. Пробное меню этой версии удалено вpreview.5.

- В0.4.0-preview.3 простые запуски известных CLI из поля команды автоматически
  включают TUI. Аргументы, составные команды и неизвестные инструменты сохраняют
  ручное переключение Ctrl+Shift+I. Автовозврат требует совместимых OSC133-маркеров
  и совпадающего приглашения родительской оболочки; при другом/динамическом prompt
  можно явно вернуться к командному режиму через меню. Пустые стартовые строки
  разметки после первоначальной очистки не попадают в журнал; сам VT-экран сохранён.
  Повтор старого экрана при последующем физическом resize не дедуплицируется вслепую.

- В0.4.0-preview.2 исправлена регрессия обычной оболочки изpreview.1:
  нативное поле команды, выделение/удаление, Tab и Ctrl+Up/Down восстановлены.
  Единая область TUI включается в отдельных CLI-профилях или явно через
  Ctrl+Shift+I. Ctrl+Up/Down в TUI служат чтению; объект системной каретки
  сохраняется для доступности, её лишнее изображение скрывается.

- В0.4.0-preview.1 реализована единая область ввода/чтения, эхо только
  подтверждённой видимой вставки и явное живое управление в нативном TUI-диалоге.
  Фактическую речь NVDA и удобство Kimi после этих изменений проверяет человек.
  Эхо может объединять быстрые символы; неизвестная/неоднозначная вставка,
  скрытый курсор без подтверждённого положения и смена геометрии требуют
  обычного чтения экрана. Поиск нового вывода не определяет смысл «ответа AI».

- В0.2.0-preview.2 исправлен прямой ввод через отдельное нативное поле с
  живым VT-текстом и кареткой. Обратная связь после явной навигации сравнивает
  видимые строки, а не семантику произвольного CLI. В0.3.0-preview.1 учитывается
  однозначный перенос fg/bg/inverse между строками и переход видимого курсора.
  Одиночная смена цвета, смена темы и неоднозначность остаются тихими; при скрытом
  VT-курсоре используется однозначный программный курсор или подтверждённая
  позиция видимого ввода; без них — конец документа. Две произвольные custom-style строки
  без признака обычного оформления могут потребовать ручного чтения.
  Проверка реальной речи NVDA и мерцания Kimi после исправления остаётся ручной.
- Речь NVDA, реальный вход/модель Codex, удалённый SSH, рабочие WSL/Docker
  сценарии и запуск на втором чистом ПК/VM требуют ручной проверки.
  Наличие WSL и Docker на машине пользователя подтверждено; прежний probe
  показывал недоступный daemon и только docker-desktop в WSL, а не отсутствие ПО.
- При fallback Ctrl+Shift+D открывает обзор любого TUI; список строк здесь не является меню CLI:
  по умолчанию он перемещает только чтение. Явный режим «Управлять клавишами TUI»
  передаёт только нажатые пользователем клавиши. Возможное выделение — подсказка по оформлению.
  Размер обзора ограничен256строками/512колонками/65536символами; об усечении
  сообщается, полный доступный документ остаётся в обычном reader.
- TUI-адаптер закреплён за Codex CLI0.164.0 startup Folder access проверенного
  профиля. Fixtures source-derived; живой trust capture не подтверждён.
  Первоначальный автоматический capture отклонён с `blocked by policy`.
  Другие экраны/версии работают через обычный доступный терминал и обзор.
  Изоляция собственного worker не является песочницей сторонних плагинов.
  Таймаут/ошибка worker отключает mapped actions; повторный анализ — явным
  Ctrl+Shift+D. Работающая PTY-сессия не перезапускается.
- Обнаружение Codex/Kimi/Claude/Gemini проверяет только локальные version/help,
  не реальный разговор/модель/разрешение. Подтверждены Codex0.164.0, Kimi2.3.3,
  Claude2.1.240 и изолированный Gemini0.65.0; последний установлен только под target
  с отключёнными install scripts/optional dependencies. Его native keytar/node-pty
  и полноценный TUI этой установкой не проверены. Общая пользовательская установка
  Gemini не выполнялась. Обычный TUI-профиль сохраняется при неизвестной версии;
  AX-профиль предлагается только при подтверждённых version/help флагах.
- App Server — отдельный read-only text frontend0.164.0 с ограниченным набором
  событий и разовыми command approvals. Нет импорта прошлых threads, файлов,
  network/persistent permissions или автоматического повтора в PTY.
- В Git for Windows2.55.0.windows.4 supplementary Unicode во введённой
  интерактивной команде может превратиться в U+FFFD. Изолированный probe
  подтвердил: входные UTF-8 bytes `41 f0 9f 98 80 42` сохраняются в ConPTY
  как D83D+DE00 KEY_EVENT_RECORD; clean Bash возвращает `41 ed b8 80 42`.
  Потеря локализована после нативного ввода на пути Git/MSYS. Кириллица/CJK,
  combining и генерируемый самим Bash emoji проходят. Команды намеренно
  не переписываются и не сохраняются во временные скрипты ради обхода.
- All озвучивает устойчивые строки, а не каждый пиксель/изменение строки TUI.
  Неоднозначные перерисовки доступны для чтения вручную. История ограничена.
- Новое окно — отдельный процесс. Недавние профили содержат начальную папку;
  команды `cd` внутри shell не превращаются в автоматически сохраняемое состояние.
- Блокировка конфигурации не ждёт другое окно: занятой файл/конфликт нужно
  открыть и сохранить заново. Пути конфигурации через reparse points отвергаются.
- Setup и EXE не имеют подписи издателя. Setup использует системный .NET
  Framework bootstrap; portable EXE не требует Rust/Build Tools/.NET/VC Runtime.
  Проверку на чистой Windows этим утверждением не подменяем.
- CI подготовлен в репозитории; без push он не выполнялся на GitHub.
  Реестр Проводника не меняется при обычном запуске/установке. Его реальная
  регистрация и поведение Explorer ожидают явного пользовательского запуска.
- Автотест реального file-symlink не смог создать ссылку из-за Windows1314;
  повышения прав не запрашивалось. Пять настоящих directory-junction с
  внешними sentinel-файлами проверили ту же защиту путей успешно.
