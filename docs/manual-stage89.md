# Проверка этапов 8–9

Этап 8 проверяется сборкой `target/stage8/bks-app.exe`, этап 9 — соответствующей
готовой сборкой с адаптером Codex. UIA Notification подтверждает событие
доступности; его получение не подтверждает произнесённую NVDA речь.

## Изолированная автопроверка

```powershell
pwsh -NoProfile -File scripts/check-stage89.ps1 -PrepareOnly
pwsh -NoProfile -File scripts/check-stage89.ps1 -Exe target/stage8/bks-app.exe -Mode Notifications
pwsh -NoProfile -File scripts/check-stage89.ps1 -Exe target/stage9/bks-app.exe -Mode Tui
```

`-Mode All` выполняет оба сценария на одной готовой сборке. `-Artifacts`
задаёт каталог результатов; по умолчанию это `target/stage89-check/`.
Скрипт переходит в Windows PowerShell MTA для работы UIA и повторно использует
native helpers этапа 7. `-PrepareOnly` компилирует helpers и фикстуру, не
запуская приложение или CLI. `summary.json` различает `passed`, `failed`,
`skipped` и `error`; `results.txt` содержит краткие проверки.

Каждый сценарий создаёт собственные PID и APPDATA. Настоящий Codex, SSH,
пользовательские транскрипты, глобальные клавиши и буфер обмена не используются.
APPDATA задаётся только в окружении дочернего BKS Term. Учётные данные,
сетевые настройки и CODEX_HOME скрипт не читает и не меняет.

Для TUI компилируется локальная C# console fixture `codex.exe` внутри своего
APPDATA. Она возвращает `codex-cli 0.164.0` для `--version`, выводит сохранённый
[официальный образец Folder access с sandbox footer](../crates/bks-app/tests/fixtures/tui/codex-0.164.0/official-folder-trust-sandbox-70x14.txt)
и пишет полученные тестовые байты в собственный `input-<PID>.bin`. Сведения о
происхождении образца и точных клавишах находятся в
[README фикстур](../crates/bks-app/tests/fixtures/tui/codex-0.164.0/README.md).
Такой запуск проверяет связь VT → распознавание → native UIA → PTY на известном
образце; совместимость с живым Codex им не подтверждается.

`Tui` проверяет:

- распознавание без открытия окна, перемещения фокуса или записи в CLI;
- явное открытие, полный readonly EDIT/TextPattern с путём, предупреждением,
  обоими вариантами и sandbox footer;
- нативный LISTBOX/SelectionPattern и смену выбора стрелкой без передачи байтов;
- Enter в тексте, Escape и кнопку закрытия без подтверждения исходного CLI;
- изменение исходного экрана: старый контекст остаётся, список и отправка
  отключаются, причина приходит через UIA Notification;
- запрет уже поставленной в очередь команды устаревшей кнопки;
- отдельный свежий процесс: только явный Invoke первой кнопки передаёт `1` и CR
  один раз в тестовую фикстуру.

`Notifications` проверяет сохранение каждого из трёх режимов через меню,
поведение после нового запуска, реальные UIA события новых строк и пределы
размера/частоты, повторные перерисовки, фоновую вкладку и однократное завершение
с кодом 7. Сравнение timestamps событий допускает 800 мс между пакетами при
производственном интервале 1 с. Сохранённый текст и события относятся только
к известной тестовой фикстуре.

## Ручная приёмка NVDA: управление речью

Во всех пунктах отдельно записать версию NVDA, сборку BKS Term, масштаб Windows
и результат. Автопроверка не заменяет эту приёмку.

1. В меню «Профили» найти «Озвучивание: весь новый вывод», «Озвучивание: только
   важное» и «Озвучивание: чтение вручную». NVDA сообщает названия и выбранный
   режим; после выбора фокус остаётся ожидаемым. Перезапустить приложение и
   проверить сохранённую отметку. Новый профиль настроек начинает с «только
   важное».

2. В своей тестовой PowerShell-вкладке выбрать «весь новый вывод» и выполнить
   конечный поток:

   ```powershell
   1..12 | ForEach-Object { [Console]::WriteLine(('BKS89_NEW_{0:D2}' -f $_)); Start-Sleep -Milliseconds 80 }
   ```

   Новые устойчивые строки объявляются порциями, речь не захватывает весь старый
   журнал. Пакеты ограничены, частый поток не создаёт непрерывную очередь речи.
   Полный сохранившийся текст остаётся доступным в журнале/экране для чтения
   по требованию.

3. Выполнить только в своей тестовой вкладке перерисовку одной строки:

   ```powershell
   1..40 | ForEach-Object { [Console]::Write("`rBKS89 progress $_ percent"); Start-Sleep -Milliseconds 50 }; [Console]::WriteLine()
   ```

   NVDA не повторяет каждое изменение прогресса. Вручную прочитать итоговую
   строку через выбранный текстовый источник. Проверить настоящее TUI со
   спиннером отдельно, если оно уже доступно; не запускать сторонние среды ради
   отметки в отчёте.

4. Повторить новые строки в режимах «только важное» и «чтение вручную»:
   автоматического чтения строк нет. Завершение/ошибка активной тестовой сессии
   объявляется один раз в «только важное» и не объявляется в «чтение вручную».
   Ответы на явные действия — выбор настройки, отправку команды, поиск —
   остаются доступными.

5. Во время конечного потока переключиться на другую свою вкладку. Фоновый
   вывод не прерывает речь и не воспроизводит накопленный текст при возврате.
   Проверить также переключение из BKS Term в другую программу: возвращение
   не должно воспроизводить старый вывод. Полный текст читать по требованию.

## Ручная приёмка NVDA: настоящий Codex CLI 0.164.0

**Живой Folder access пока не подтверждён этой инструкцией или source-derived
фикстурами.** Автоматический повтор интерактивного захвата настоящего CLI не
входит в скрипт. Следующие действия выполняет человек в собственной разрешённой
тестовой папке и при уже установленной поддерживаемой версии.

1. Открыть отдельную вкладку профиля «Codex CLI 0.164.0». Адаптер действует
   только для проверенного direct native executable этого профиля. При запуске
   `codex` внутри обычной PowerShell/SSH-вкладки нативный адаптер не ожидается.
   Если полного стартового Folder access нет, отметить сценарий как
   **не проверен**; не менять доверие, авторизацию или настройки CLI ради его
   появления.

2. При полном Folder access проверить короткое сообщение о доступном диалоге.
   Фокус остаётся на прежнем элементе, окно само не открывается, доверие не
   подтверждается. Нажать Ctrl+Shift+D либо выбрать «Профили → Доступный диалог
   TUI». Начальный фокус — в исходном тексте для чтения.

3. Прочитать и выделить текст стандартными командами NVDA/EDIT. Проверить
   полный путь, предупреждение об автоматическом выполнении кода из настроек
   папки, `Trust and continue`, `Quit` и весь footer. Если присутствует
   создание Windows sandbox, оно остаётся в тексте. Проверить обычное копирование
   вручную; автоматический скрипт буфер обмена не использует.

4. Enter в исходном тексте сохраняет окно и не подтверждает запрос. Tab и
   Shift+Tab обходят текст, список и две кнопки. NVDA сообщает имена пунктов,
   выбранный пункт, назначение кнопок и disabled-состояния. Стрелки в списке
   меняют только местный выбор. Esc и «Закрыть без отправки» закрывают это окно
   и возвращают ожидаемый фокус, оставляя исходный запрос CLI без ответа.

5. Для проверки устаревания открыть окно, затем изменить исходный экран CLI
   разрешённым действием или переключиться на другую свою вкладку. Выбор и
   отправка отключаются; NVDA получает причину, старый текст остаётся доступным.
   Фоновое изменение не переводит фокус в окно. Старый выбор отправить нельзя;
   актуальный экран открывается новым явным действием после закрытия старого
   окна.

6. Передача варианта — отдельное явное действие кнопкой «Передать выбранный
   вариант в CLI» либо Enter при фокусе списка/этой кнопки. Выполнять её только
   для заранее разрешённого человеком выбора. Проверить соответствие варианта
   поведению CLI и однократность ввода. Для `Trust and continue` это реальное
   решение о доверии тестовой папке, поэтому данная инструкция не требует
   подтверждать его ради завершения проверки. Непройденный вариант отметить
   отдельно.

Повторить обход окна при 100%, 150% и 200% DPI, с High Contrast, длинным
поддерживаемым путём и после возврата в BKS Term. Проверить отсутствие обрезанных
кнопок, читаемый статус и сохранение фокуса. Экраны restricted/resume/back,
обрезанные пути, другие версии и неизвестные предупреждения должны оставаться
обычным терминальным текстом без угаданного подтверждения.
