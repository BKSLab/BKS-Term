## Итерация 7.1. Ограниченный вывод

Подтверждённые пределы текущей сборки: очередь PTY — 1 МиБ на сессию,
drain — до 64 КиБ на сессию. Общий poll использует до 256 КиБ за кадр и
мягкий бюджет 8 мс с обходом сессий по очереди. Журнал ограничен 512 КиБ UTF-8
и 6000 переводами LF; при обрезке остаётся до 384 КиБ/4000 LF. Индекс блоков
содержит не более 4096 записей. При trim нативный EDIT получает актуальный
ограниченный снимок с восстановлением UTF-16 selection и viewport; обычное
добавление текста остаётся инкрементальным.

Больший журнал оказался слишком дорогим для нативного EDIT: удаление префикса
занимало около 1,1 с, замена снимком примерно 1,2 млн UTF-16 единиц — 1,5 с.
Поэтому лимит уменьшен с сохранением того же нативного доступного контрола;
обоснование — [ADR 0005](decisions/0005-bounded-output-and-lifecycle.md).

Автопроверка checkpoint `target/stage7/iteration1/bks-app.exe`:

```powershell
pwsh -NoProfile -File scripts/check-stage7.ps1 -Exe target/stage7/iteration1/bks-app.exe -OutputOnly -MtaDiagnostics -PerformanceTrace
```

Результат: **19 passed, 0 failed, 0 skipped, 0 errors**. Артефакты:
`target/stage7-check/output-20261026-163456-7c58d75e/`.
Конечный поток — 30 000 строк; сохранены Unicode-хвост, selected anchor и
viewport после trim. Нативный журнал: 418 565 байт UTF-8, 4812 LF.
Максимальный WM_NULL — 320 мс при неизменном пороге 1000 мс; trace trim —
293–389 мс. Пауза генератора использует ограниченный handshake в собственном
APPDATA, чтобы исходная позиция чтения была снята до продолжения потока.
Свой процесс закрыт; речь NVDA этим не проверена.

Повторный прогон итоговой сборки `target/stage7/iteration3/bks-app.exe`:
**19 passed, 0 failed, 0 skipped, 0 errors**;
`target/stage7-check/outputonly-20261026-170308-f7a0602f/`.
Сохранены те же 30 000 строк и порог 1000 мс: 41 замер, максимум 533 мс,
таймаутов нет. Журнал — 456 497 байт UTF-8/5248 LF; Unicode-хвост, выделенный
маркер, viewport и черновик сохранены. Этот повтор проверяет совместный путь
ограниченного вывода после изменений жизненного цикла и профилей.

1. В PowerShell выполнить конечный поток, превышающий лимит журнала:

   ```powershell
   [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
   $glyphs = 'Ж中e' + [char]0x301 + [char]::ConvertFromUtf32(0x1F600)
   1..40000 | ForEach-Object { [Console]::WriteLine(('BKS7_{0:D6}_{1}_{2}' -f $_, $glyphs, ('x' * 96))) }
   [Console]::WriteLine('BKS7_' + 'FLOOD_FINISHED')
   ```

   Последний маркер должен дойти полностью. Старейшие строки удаляются по
   лимиту, журнал не растёт без ограничений. Unicode не обрывается посередине
   суррогатной пары. Лимиты очереди и объёма за один poll дополнительно
   проверяются модульными тестами; длина EDIT сама по себе их не доказывает.

2. Во время потока перейти Tab/Shift+Tab между видимыми контролами, изменить
   черновик команды и открыть справку. Окно продолжает отвечать, черновик не
   отправляется сам. Снять захват терминальной клавиатуры, если он включён.

3. Выделить строку ближе к концу сохранённого журнала, затем добавить вывод
   так, чтобы удалился только старый префикс. Выделенный текст и видимый якорь
   чтения остаются прежними, позиции пересчитываются относительно нового
   начала. Если сама выделенная строка удалена, позиция ограничивается началом
   доступного текста и не переносится к концу автоматически.

4. Повторить чтение в источниках «Журнал терминала» и «Экран терминала».
   Проверить актуальность поиска после удаления старого текста. Создать вторую
   вкладку через выбор профиля: её вывод, черновик и позиция чтения независимы.

## Итерация 7.2. Завершение и повторный запуск

Автопроверка checkpoint `target/stage7/iteration2/bks-app.exe`:

```powershell
pwsh -NoProfile -File scripts/check-stage7.ps1 -Exe target/stage7/iteration2/bks-app.exe -LifecycleOnly -MtaDiagnostics
```

Результат: **16 passed, 0 failed, 0 skipped, 0 errors**;
`target/stage7-check/lifecycleonly-20261026-164241-58ad8326/`.
Собственный CMD `/c` сохранил хвост без LF и завершился с кодом 7. Проверены
однократная запись в журнал и UIA Notification, новое выполнение по Restart,
сохранность старой вкладки/черновика. Закрытие живой CMD после подтверждения
заняло 21 мс при пороге 1000 мс; финальный тестовый процесс закрыт.

1. В отдельной тестовой вкладке PowerShell выполнить:

   ```powershell
   [Console]::OutputEncoding = [Text.UTF8Encoding]::new(); [Console]::Write('BKS7_' + 'FINAL_TAIL_Ж中'); exit 7
   ```

   Хвост без завершающего перевода строки остаётся доступен для чтения после
   завершения процесса. Состояние отличает завершение от активной сессии,
   доступен код выхода 7. Завершение не создаёт повторных речевых уведомлений
   при каждом тике и не стирает прочитанный вывод.

2. Явно повторно запустить тот же профиль. Это новый процесс: старое завершение
   и хвост не выдаются за вывод работающей оболочки. Другие вкладки сохраняют
   свои процессы, текст, поиск и черновики. При ошибке запуска доступна её
   причина; автоматического бесконечного переподключения нет.

3. Закрыть свою тестовую вкладку во время длинной команды и интенсивного вывода.
   UI не должен ждать многосекундный синхронный Drop; ввод и reader корректно
   освобождаются. Повторить несколько циклов создания и закрытия. Не завершать
   пользовательские процессы для выполнения этого сценария.

## Итерация 7.3. Нативные SSH-профили

Автопроверка итоговой сборки:

```powershell
pwsh -NoProfile -File scripts/check-stage7.ps1 -Exe target/stage7/iteration3/bks-app.exe -ProfilesOnly -MtaDiagnostics
pwsh -NoProfile -File scripts/check-stage7.ps1 -Exe target/stage7/iteration3/bks-app.exe -GitBashOnly -MtaDiagnostics
```

`ProfilesOnly`: **20 passed, 0 failed, 0 skipped, 0 errors**;
`target/stage7-check/profilesonly-20261026-165627-192e62fb/`.
Проверены доступные имена нативных полей, создание/редактирование/повторное
чтение SSH-метаданных, неверный порт, отмена и восстановление owner. Создание
профиля не запустило SSH. Защищённое поле имеет ES_PASSWORD и UIA IsPassword;
отмена не отправила значение, повторное открытие пустое, отправка завершила
локальную ReadKey(true)-фикстуру с проверкой SHA-256 тестового значения.
Открытый текст отсутствует в черновике, профиле и журнале. В аргументах самой
фикстуры хранится только ожидаемый hash; настоящие секреты не использовались.

`GitBashOnly`: **8 passed, 1 failed, 0 skipped, 0 errors**;
`target/stage7-check/gitbashonly-20261026-170131-49a479ad/`.
Настоящий Git Bash выполнил `pwd`, `git --version` и Unicode `printf` через
ConPTY/нативный журнал. Legacy-профиль с WindowsApps-алиасом исправлен при
запуске без изменения JSON. Генерация `Ж界é😀` через ASCII-аргументы
`printf` с `\u`/`\U0001F600` сохраняет UTF-8, включая `f0 9f 98 80`.

Один **failed** оставлен явно: при передаче literal supplementary-символа в
командном вводе `😀` заменяется на U+FFFD. Поле EDIT перед отправкой содержит
правильную пару D83D DE00; generated output и его hex корректны. Потеря
происходит между отправкой команды и её обработкой/эхом Git Bash; конкретный
компонент ConPTY/MSYS не изолирован. Это отдельный открытый дефект, а не
успешная проверка literal Unicode input. Новых диагностических Git-прогонов
после фиксации границы не выполнялось.

Все тестовые процессы закрыты. Речь NVDA, полный клавиатурный обход новых
диалогов, удалённая SSH-аутентификация и недоступные Docker/обычная WSL-среды
этими автопроверками не подтверждены.

Создать, сохранить и отредактировать профиль с тестовым именем и фиктивным
хостом, не запуская соединение. Проверить обход полей клавиатурой, доступные
имена, валидацию хоста/порта и отмену без изменения прежнего профиля. Путь к
ключу хранится как ссылка на файл; содержимое ключа и пароли не копируются в
профиль, отчёт или артефакты.

При наличии разрешённого тестового сервера человек отдельно проверяет первое
подключение, host key, пароль/passphrase, `sudo`, Ctrl+C, разрыв связи и явное
переподключение. Не отключать проверку ключа хоста. Секреты не сохраняются и не
включаются в речевые логи. Без сервера эти пункты остаются непроверенными.
